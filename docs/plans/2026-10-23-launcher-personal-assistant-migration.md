## 1. 目标与产品边界

推荐架构是“Launcher 托管一个独立个人助理运行时，各项目保留自己的执行器”。助理的对话、偏好、模型绑定和恢复记录独立于项目；创建 Agent、运行团队、修改项目配置等操作仍由目标项目的原生服务执行。

产品形态确定为：个人助理作为完整产品模块迁入 Launcher，用户主动打开 Launcher 或助理时即可看到桌面形象，点击形象唤起完整面板。桌面形象与完整面板共享同一助理；平台不再提供助理页面、嵌入视图、设置、桌宠入口、初始化或巡检。平台只保留普通 Agent、团队、项目等业务能力及通用受控执行接口。

用户只需表达结果，例如“在项目 A 建一个开发、审查和测试团队并运行”“把项目 B 的 Agent 模型换掉”“重启项目 A，完成后继续刚才的任务”。助理负责识别目标、检查能力、执行、等待回执和报告结果。只有目标存在实质歧义、缺少凭据、超出授权或确需破坏性确认时，才提出一个合并后的问题。

### 1.1 必须实现的结果

| 场景 | 迁移后的行为 |
| --- | --- |
| 主动打开 Launcher，尚未启动任何项目 | 默认显示收起态桌面形象；完整助理、自己的设置和模型恢复入口可用；项目离线不阻断展示 |
| 使用个人助理的任何既有功能 | 从 Launcher 助理面板可达；桌宠提供快捷交互；不要求先打开项目设置页或启动默认项目 |
| 项目启动、停止、重启或构建失败 | 助理进程和对话保持可用；依赖该项目的步骤显示等待或失败原因 |
| 多项目和同项目多实例 | 操作绑定明确的 projectId、instanceId 和配置权威，不因窗口切换而改目标 |
| 关闭工作台、Launcher 主窗口、助理面板或桌面形象 | 只改变对应窗口的展示；助理由 Launcher 与托盘继续托管，明确退出 Launcher 才关停服务 |
| 新建 Agent、改配置、用户名、头像、壁纸、设置 | 通过已有受控动作完成，按真实作用域说明影响范围 |
| 一句话创建并运行团队 | 自动形成团队规格、创建角色、启动原生工作流并跟踪成果 |
| 连接中断或写入响应丢失 | 先查原操作和目标状态；不重复创建对象或启动团队 |
| 重启 Launcher 或升级助理 | 保存会话和操作状态；重新启动后恢复可确认的工作 |
| 未配置模型或模型失效 | 结构化恢复入口仍能启动、查看状态、修改连接；不承诺此时仍能自然语言推理 |

### 1.2 本次迁移不扩大的范围

首版限定当前桌面用户、已登记的本机项目和实例。退出 Launcher 后无需继续运行，不新增 Windows 系统服务，不开放公网控制口，不自动部署、发布或提权。普通 Agent、项目任务、团队执行、Git、项目记忆及其授权继续留在各自项目。Companion 隔离规则继续生效，桌宠展示不获得普通 Session 的额外执行权限。

### 1.3 最终归属与复用边界

| 范围 | 迁移后的唯一归属 | 平台侧要求 |
| --- | --- | --- |
| 助理聊天、历史、形象、设置、偏好、私有记忆、个人事务、派遣观察和主动调度 | Launcher 托管的助理运行时与 UI | 删除对应产品入口、运行装配和助理专用 API；不保留 iframe、嵌入视图或隐藏的第二套助理 |
| 助理身份、模型绑定、直属 Session 与自己的授权策略 | 助理专属原生运行根 | 新项目不创建 PA Agent/Session；旧身份仅可作为有退役条件的迁移来源与历史任务关联 |
| Agent/团队/项目的创建、配置、执行与成果 | 各项目原生业务服务 | 提供通用认证、对象 ACL、业务动作及回执接口，不承担个人助理规划、人物或偏好 |
| Session/LLM/Journal、模型配置事务、消息及工具基础设施、VUI | 同一仓库中的共享源码与契约 | 普通 Agent、平台规划师和 Companion 继续复用；按调用者拆分装配，禁止复制后分别演进 |

最终关闭条件同时检查 Launcher 的功能完整和平台的功能退出；仅搬页面或关闭旧入口不算迁移完成。旧数据备份不等于产品功能保留；在途回执适配不接受新助理业务，条件关闭后移除，见第 7.5 节。

### 2.1 当前 API 基线

上一轮基线记录了 738 个已注册 HTTP operation：24 个只读网关映射、42 个原生动作映射、672 个受限、专用或尚未映射的 operation。另有 32 项新增语义动作完成真实模型实测。语义动作数量和 HTTP operation 数量不能相加，也不能据此宣布全量 API 已接入。

这些数字只表示上述代码基线和验收快照。实施时必须从目标实例的注册 OpenAPI 与动作注册表重新生成清单；接口文档存在、工具可见、获得授权、实际执行成功分别验证。迁移关闭要求已接入能力完整迁移，并对全部注册 API 给出可解释的支持状态；剩余可面向用户开放的能力按业务分组补齐，不要求把内部接口全部暴露。

## 3. 推荐架构与运行方式

~~~mermaid
flowchart TB
    U["Launcher 完整助理面板"] --> E["Electron main：身份、项目注册与生命周期"]
    V["桌面形象：打开即显示"] --> E
    V -.->|"点击唤起同一助理"| U
    E <-->|"私有运行通道"| A["独立 Python 助理服务"]
    A --> S["助理专属存储：原生 Session、偏好、操作记录"]
    E -->|"已登记项目与权限快照"| A
    A <-->|"闭合业务调用"| B["宿主内复用原生项目 SDK"]
    B --> P1["项目 A 原生 API 与执行器"]
    B --> P2["项目 B 原生 API 与执行器"]
    P1 --> D1["项目 A Agent、Journal、团队与任务"]
    P2 --> D2["项目 B Agent、Journal、团队与任务"]
~~~

图中的 B 复用在可信 Python 宿主内，不增加进程或规划模型。Electron 管登记表、权限快照和项目生命周期；SDK 直接调用目标的受控业务 API，目标执行器和原生回执仍是项目任务权威。

### 3.1 进程与发布包

1. 一个桌面用户、一个 Launcher owner、一个常驻助理服务。Electron 单例锁之外增加 profile 级服务租约，绑定 PID、进程创建时间、releaseId 和启动 nonce；端口存在不能作为接管依据。
2. 助理运行在独立、版本化的 Python 包和依赖环境中。工作目录、模块搜索路径、解释器及 UI 资源均不依赖当前项目 checkout、项目 .venv 或工作台 web/dist。
3. 首版复用现有 Python Session/LLM 能力，不把执行链重写成 Node，不引入 LangGraph 或 Agents SDK 作为新的运行内核。
4. 固定一个助理专属原生运行根，在初始化任何 Session/Agent 单例前解析完成。它只承载全局助理，不装载不同项目的 Session Store，也不启动项目科研、团队恢复、构建和代码索引后台任务。
5. 独立 bootstrap 只组合助理所需模块；不得直接启动完整工作台 app，再期待开关关掉全部副作用。
6. 产品启动采用 pythonw 或现有无控制台原语，shell=false，并使用助理专属进程 owner。项目 stop/restart/reap 不得覆盖该 owner。
7. 服务就绪分为 process_alive、transport_ready、session_ready、model_ready。前三项完成后才允许提交对话；model_ready 失败进入可恢复状态，不能用 HTTP 200 代替模型可用证明。

子进程环境按明确清单构造，清除项目 PYTHONPATH、PYTHONHOME、Git hook 上下文及意外数据根覆盖；配置源由已验证的 configAuthorityId 解析。保留必要的用户网络和凭据解析环境，不把整个项目环境当作可信启动配置。

### 3.2 服务通信

为保留现有 Session DTO 和事件形状，首版采用“私有 loopback 助理 API + Electron IPC 代理”。Python 仅监听 127.0.0.1 的动态端口，不使用固定 :8765，不提供 Launcher 实例注册、项目生命周期或桌面窗口控制接口。

- Electron 通过仅传给所属子进程的环境传递 generation 专属 bearer；子进程在原生 import 前移除该环境变量。就绪文件只原子发布协议、role、instanceId、PID 与动态端口，不含凭据；main 再在自己的 Job 内核对 generation 并认证健康。profile、封存 release 和权限快照由 owner 绑定，不能只凭 PID 或端口接管。凭据不得放在 argv、URL、日志或 renderer。
- 助理 API 的业务和事件请求全部认证；不沿用公开 control-token 获取入口，不设置宽泛 CORS。Electron 对每条 IPC 校验 sender、主 frame、窗口角色和参数。
- 面板和桌宠只使用窄的 typed IPC 方法，由 main 转发对话与事件，不获取项目或助理 token。
- 项目业务 API 由可信 Python 宿主直接复用现有闭合 SDK，私有项目凭据仅留在宿主 profile。Electron 下发已登记项目和权限快照；模型和 renderer 均不接收凭据、URL 或根路径。未知动作和未迁移 API 默认不可执行。
- 项目生命周期请求单独经闭合 main bridge，复用 Electron 原生命令、队列、supervisor 和回执；不接收 shell、任意 URL、任意文件路径或自由 HTTP method。该桥的稳定 command 关联与重启恢复未验收前，不开放为模型动作；SDK 不承担项目启动/停止。
- 闭合请求与响应须有长度上限、超时和取消语义；需要恢复的写入保留稳定 requestId。日志走独立有界文件，不混入协议；pythonw 不依赖 sys.stdin/stdout，后台子进程复用无控制台和 Job 原语。
- 协议与 API 分别版本化。主版本不兼容时拒绝执行并提供恢复入口；未知可选字段可忽略，未知动作默认拒绝。
- 原生 Session 事件只增加传输适配。事件携带 sessionId、turnId、seq 和 cursor；断线按原生 Journal 水位重放，缓冲超限返回 resync_required。不得由 IPC 或全局操作表生成另一份 transcript。

私有 HTTP 只承载助理 Session 与展示服务；项目 start/stop/restart 和进程回收仍只由 Electron main 执行。因此需要扩展 ADR 0009 的 Python 服务角色，而不是迁回 Python Launcher 控制平面。

## 4. 数据归属与配置权威

### 4.1 唯一写入者

| 数据 | 写入权威 | 迁移规则 |
| --- | --- | --- |
| 全局助理身份、人物和 ToolPolicy | 助理专属原生 Agent 目录 | 一个全局对话身份；显示名与稳定 profileId 分离 |
| 全局助理对话 | 助理运行根中的原生 Session Journal | 同一 Session 引擎读写，不以消息缓存替代 Journal |
| 助理偏好、桌宠选择、主动程度 | 助理专属设置服务，带 revision | 复用现有字段与校验；只迁移选定来源 |
| 助理模型绑定 | 全局助理原生 Agent 配置 | 从共享模型目录引用，保留显式选择和版本 |
| Provider、模型目录、用户名、全局主题等 operator 设置 | 现有外部 operator config 与原生事务 | 不复制第二套可写 TOML，不改变旧字段原有作用域 |
| 项目 Agent、团队、Session、任务成果 | 目标项目原生 service/Journal/WorkRun | 不迁入全局助理目录 |
| 项目 Inbox 和业务回执 | 原生 Kernel/Inbox/执行器 | 全局侧只保存关联 ID、状态投影、游标和证据引用 |
| 项目/实例注册与生命周期 | Electron main 原生注册表与命令队列 | 助理不得自行改 instances.json |
| 全局操作关联记录 | 助理原生持久存储中的最小记录 | 只管理意图、稳定键、目标引用和恢复游标；复用持久化原语，不取代原生任务状态 |
| 旧助理历史 | 经验证的只读原生历史归档；旧文件保留为回滚源 | 不拼接不同来源 Journal，不重放旧工具调用 |
| 头像、壁纸、附件 | 对应作用域的原生资产服务 | 使用稳定 assetRef，禁止把项目临时 URL 当作全局资产 |

### 4.2 助理存储布局

新增专用路径解析器。建议默认位于 %LOCALAPPDATA%/Vibelution/assistant/profiles/<profileId>/，遵循后续明确记录的单独覆盖配置。这个路径及覆盖项是待实现设计，当前产品尚无此约定。

| 子目录或文件 | 用途 |
| --- | --- |
| profile.json | profileId、schemaVersion、迁移来源和当前 owner epoch；不镜像 Agent 可编辑配置 |
| data/ | 助理原生运行根所需的 Agent、Session、插件账本与设置 |
| assets/ | 已验证并归属助理的头像、附件及展示资产 |
| 原生操作关联存储 | 请求、步骤、去重键、审批关联和回执游标；具体介质由 M2 验证后确定，不预设独立 operations.sqlite |
| migrations/ | 迁移 manifest、哈希、状态和回滚检查点 |
| runtime/ | 租约、短期连接、进程 owner 和就绪记录 |
| logs/ 与 cache/ | 有界诊断与可重建投影，不承担业务权威 |

路径解析不能靠删除 project identity 后让旧函数回退到源码根，也不能向父进程设置 VIBELUTION_DATA_HOME。助理进程的根在启动后保持不变；现有普通项目路径行为保持不变。

### 4.3 模型与共享配置

- 复用 config/operator_config_transaction.py 的跨进程锁、CAS、字段级修改、校验和回滚；证明助理与两个工作台同时修改时不会丢失更新。
- 为每个实际配置源生成不暴露路径和密钥的 configAuthorityId。同名 projectId 不代表使用同一 operator config；批准和回读均绑定真实配置权威。
- 助理拥有独立模型绑定和最后一次验证可用的连接快照；快照记录模型 ID、协议参数和 credentialRef，不复制明文密钥、不成为第二个模型编辑目录。
- 模型删除、Provider 删除和引用扫描必须覆盖常驻助理及其运行中 Turn；项目离线或引用权威不可确定时，不宣称“没有引用”。
- 使用既有凭据解析。缺凭据时通过受保护的凭据入口补充；不让模型读取密钥，不在普通对话中要求用户粘贴密钥。
- 模型正在使用时，修改后的默认绑定对后续 Turn 生效；正在执行的 Turn 保持受理时快照。
- 切换助理自身模型先做真实连接验证，再事务提交绑定；失败保留原绑定。备用模型必须是用户已授权的候选，不静默切到新的供应商。
- 模型完全不可用时保留确定性的连接修复、状态查询、项目启动和日志摘要入口。自然语言能力恢复以真实模型调用为准。

初始化配置属于迁移交付范围。首版只适配现有原生配置定义，不新建通用 Agent 配置框架，不在 Launcher 维护第二份 persona、Prompt、ToolPolicy 或模型目录。以下是拟议初始化契约；表中现有默认值是复用起点，不表示全局运行根与受认证项目调用已经实现。

Launcher 只负责编排初始化和展示结果。配置写入仍通过各自 service，配置页面与自然语言动作读取同一原生记录。模板目录与能力说明从现有注册表投影，避免再手工维护一套角色清单和工具白名单。

没有可用模型时仍完成身份和存储初始化，展示可操作的连接修复入口，并保持 model_ready=false；不提交无法执行的自然语言 Turn。密钥只进入已有受保护入口。模型已可用时不重复要求用户填写 Provider、模型和人物信息。

项目侧只有通用调用授权与原生执行器，没有助理初始化。迁移来源的禁用、归档或自定义零工具策略进入差异核对，不能通过创建全局新身份绕过；有效权限不因搬迁扩大。旧任务的身份引用只用于有范围、有期限退出条件的回执承接，不能恢复规划、巡检或受理新任务。

### 4.6 新建 Agent 与团队的初始预设

普通协作 Agent 与开发团队必须采用不同的原生预设。当前 agent_create 默认是 assistant_worker、prompt-chat-default、request_approval 权限预设，仅启用 agent_message_tool；网络为 none、写入为 private、mutation 为 controlled，工具调用上限为 8，allowSubagents=false、allowWakeMessages=true。它适合接收任务和返回结构化回执，创建成功不能作为具备文件编辑、测试或 Git 能力的证明。

用户说“新建一个 Agent 帮我做事”时，助理根据任务选择现有可用预设，并补齐以下配置；可从已知上下文确定的内容不再逐项询问。

| 配置组 | 自动补齐规则 | 必须保留的边界 |
| --- | --- | --- |
| 目标与身份 | 固定项目/实例、显示名、原生 roleKey、职责；保存来源操作与稳定 requestId | 不跨项目复用对象 ID；重复指令的恢复不能再次创建 |
| 模型与参数 | 绑定目标配置权威下可解析且已授权的模型；能沿用有效默认值时直接复用 | 不把另一配置源的 modelId 当有效绑定；不自动创建付费 Provider 或换供应商 |
| 任务与验收 | taskProfile 写明目标、输入/输出、范围、成功证据、停止条件和回执关联 | 原生 Session 保存正文；配置和操作记录只保存所需字段及引用 |
| 工具与权限 | 根据原生角色/权限预设选择完成任务所需能力，再计算实际有效 ToolPolicy | 权限提升按既有规则处理；不能通过创建新 Agent 获得超出来源授权的能力 |
| 执行资源 | 复用原生模型参数、工具上限、超时、团队并发配置和已有预算控制 | 未设置价格或总预算时不虚构成本承诺；派遣链不自行放大并发或调用额度 |
| 记忆与反馈 | 各 Agent 保留自己的私有记忆；回执绑定来源消息和个人助理任务协议 | 不共享私有 memory 目录，不把消息投递成功当作任务成果 |

一键团队首版复用当前 dev-team 模板，其规划、开发 A、开发 B、评审角色从原生角色库读取。现有 PA 工作流按角色串行执行；并行开发、独立测试角色和自动合入都不属于当前已验证能力。一键开发团队交付必须选择并验证具备相应工作目录、工具及授权的原生执行预设；缺少执行预设时列为 M5 的交付缺口，仅有消息权限不能宣称已能开发。角色数量、模型覆盖和权限变更集中生成一次差异，已在授权内的默认组合直接创建并运行。

启动运行前读回每个成员的实际模型绑定、有效工具、权限范围、工作目录和任务职责；有成员无法执行其职责时不启动整套工作流。运行验收同时检查原生运行状态与实际成果；涉及开发时还需文件、测试等证据，不能仅以四个角色都回复文字作为开发成功。

### 4.7 初始化、升级与恢复

1. **先检查再创建**：解析固定运行根和 configAuthorityId，查已有 profile、原生身份、直属 Session 及迁移记录。有旧数据先走选定来源迁移，不把“启动新进程”当成“全新安装”。
2. **显式且幂等地应用**：沿用原生 setup 状态，按全局 profile 和稳定初始化键锁定；记录原生 ID，逐项创建或恢复。项目只握手和授权，不初始化 PA。GET/页面轮询不触发初始化。重复启动、并发窗口和中途崩溃不得产生第二个助理或直属 Session。
3. **区分完成程度**：持久化身份、配置和 Session 后才标记 session_ready；模型探测通过后才标记 model_ready。失败保留 pending 和明确原因，只恢复未完成步骤；重复身份或绑定冲突不靠删除、重建自动解决。
4. **验证生效值**：从原生服务读回 persona/task、偏好、模型、ToolPolicy、有效可执行工具和直属 Session。在隔离验收中用真实模型完成一次有证据的查询及一项已授权、可恢复的受控写入；配置保存成功不能替代行为验收。用户首次安装只做必要连接探测，不为自检创建业务对象；后续普通启动复用有效状态，不自动重复模型验收。
5. **保护用户修改**：拟议在原生 Agent metadata 记录 presetId、presetVersion、系统写入字段与 provisionedFingerprint，复用 revision/CAS；这些只是来源信息，不是另一份可编辑配置。升级只迁移可证明未修改的默认字段，用户改过的姓名、人物、偏好、模型、零工具策略等原样保留。
6. **权限变更单独判断**：新增工具、项目授权或网络/写入权限不能仅因预设版本升级自动启用。复用既有精确历史快照升级规则，并在 M0 固化允许自动迁移的字段；无法确认来源时保留现状。
7. **重置有明确范围**：用户要求恢复默认时，先计算对应 Agent/预设字段差异，按原生授权应用；不连带删除会话、记忆、凭据、团队或任务。升级和重置均保存可读回的版本及结果。

这部分只新增独立运行根适配、通用调用授权和必要初始化元数据；复用现有创建、模型绑定、配置事务、直属 Session、角色模板与任务去重。M0 先列出可以直接调用的原生入口及缺口，避免先复制全部默认配置，再长期维护两套初始化逻辑。

## 5. 项目连接与受控 API

### 5.1 项目寻址

Electron 只下发已登记项目的根、注册 epoch 与权限快照，可信宿主按快照解析 SDK 目标。模型提供 projectRef 或明确的目标对象，不能提供网络地址、根路径或可信身份。目标绑定、能力 revision、配置权威及实例 generation 按各原生 API 的实际契约校验；这些字段不是由模型填写，也不把规划中的完整身份 envelope 写成所有入口已经实现的保证。

默认目标可继承本次对话明确固定的项目。执行前展示或在操作回执中说明目标；切换工作台窗口不会修改已排队操作。两个项目重名、目标实例改变、配置源改变或对象已移动时，重新核对，不能猜测。

项目离线时，已授权操作可经 Launcher 原生命令队列按需启动该项目，并等待 routesReady、身份和能力握手。只为读取缓存状态时不唤醒项目。只有新建或管理未登记目录时才走单独的项目登记流程。

### 5.2 身份与权限适配

采用“一个全局助理 + 项目通用受控执行接口”。项目侧登记受认证的外部调用主体，不要求存在 canonical PA、本地助理直属 Session 或 PA Inbox。调用主体是授权和审计记录，不带模型、人物、聊天历史或巡检；不把原有 PA 对象换个名称继续运行。

M0 定义版本化的外部 principal 与原生动作授权上下文。最小内容包括 issuer/profileId、全局 sourceSessionRef/sourceTurnRef、projectId/instanceId/instanceGeneration、configAuthorityId、action、参数 hash、requestId、有效期及策略/能力 revision。issuer、subject 和目标授权由服务端握手建立，模型只能选择动作与业务参数，不能自行指定可信身份。全局会话引用不得冒充项目内 sessionId/turnId。

目标 gateway 先认证并拒绝缺失/过期/错误 audience 的请求，再按全局助理策略、项目授权、动作能力、目标对象 ACL 与原生业务前置条件的交集进行最终动作授权。它记录授权决策与受理关联后才调用提取出的原生领域 service，业务结果随后从原生来源核验。现有 ToolPolicy 规范化、动作规则、审批 DTO、配置事务和 ACL 能复用的部分直接复用；不能因没有 Agent runtime 而进入 system_context 的默认放行路径。

知识、私有记忆和 Inbox 的 ACL 尤其不能用伪造 Agent 身份绕过：提供明确的 operator/外部主体授权路径并证明对象范围；原生服务尚不支持该主体时拒绝并说明缺口。全局助理自己的策略与项目许可都不能赋予其他 Agent 私有 Inbox 的任意读取权。

当前 personal_assistant_tools.py 的 wrapper 依赖项目内唯一 PA，不能作为新 gateway 的鉴权实现；在迁移源尚未退出时保持其旧身份门，退出后从平台装配中移除。Launcher 端工具使用自己的原生身份校验并调用新 transport。禁止把全局 Agent ID 填进旧 runtime、伪造聊天 Turn、传 governed=true 或直接调用未授权 handler；需要扩展共享授权核心时拆独立任务，证明普通会话和 Companion 契约保持原行为。

现有按 (agent_id, action) 记忆的低风险操作窗口，需要在新入口绑定 profileId、projectId、instanceId、作用域、动作和到期时间。项目 A 的批准不得用于项目 B。权限提升、远端 push/PR/发布、破坏性删除仍按既有规则处理。

prepare 是拟议网关阶段；优先复用现有审批 DTO、原生策略和已具备的持久回执，M0 明确列出持久化与进程内状态及缺口，需要跨进程恢复时只补最小关联。批准绑定上述作用域、参数 hash、策略/配置版本与到期时间，执行和重启后均由目标授权门重验，不改变普通 Session 临时 grant 的语义。若目标批准已经过期或丢失，重新 prepare 并按当前原生策略请求批准；操作关联记录中的 approvalRef 本身不构成有效授权。

M3 的首个强制切片是在没有项目内 PA Agent/Session 的隔离项目中完成：受控查询、一次幂等写入、派遣给原生 Agent、收到与原操作关联的原生回执，再覆盖拒绝与撤销负例。若 Kernel 目前只接受本地 Agent 作为消息来源，新增有明确外部主体/回执路由的通用入口适配；不静默创建项目内 PA 兜底，不借此改写普通 Agent 的 admission 或消息正文权威。该切片未通过前不切换活数据，也不宣称授权改造完成。

### 5.3 拟议能力和动作契约

以下是设计中的逻辑接口，路径和字段尚未在产品实现；M0 输出正式 DTO/OpenAPI，禁止把本节当成可调用 API 文档。

| 逻辑操作 | 必需信息 | 返回与约束 |
| --- | --- | --- |
| projects.list/get | 用户级身份、分页与过滤 | 登记项目、实例、连接状态、最后确认时间；不暴露 token |
| project.capabilities | 明确目标、协议范围 | operation/action、schema、风险、作用域、支持状态、版本与恢复能力 |
| action.prepare | action、结构化参数、目标、operationId | 参数校验、差异、原生 revision、approvalRequired；不产生业务写入 |
| action.execute | prepareId、相同参数摘要、授权引用、原 revision、已认证调用上下文 | operationId、受理状态、native IDs；202/accepted 不代表完成 |
| operations.get/reconcile | operationId、同一目标 | 原生读回结果、证据和下一步；不会自动重新发出写入 |
| operations.cancel | operationId、预期状态、原生 Turn/run ID | 取消观察或请求原生停止；区分两者 |
| events.subscribe | 用户身份、项目过滤、cursor | 有界元数据事件与来源引用；过期 cursor 要求快照重建 |

每个能力描述至少包含作用域、前置条件、参数 schema、风险、副作用、授权方式、原生 owner、幂等模式、成功证据、超时与恢复方式。字段投影来自现有动作和注册 OpenAPI，不维护第二份手工全量接口清单。

同一动作描述的 scope 决定 adapter 路由：助理自己的配置/事务走独立宿主，项目动作走目标 gateway，共享 operator 配置走已核对的配置权威，生命周期命令走 Electron main。Launcher 内保留的工具名不是本地项目调用许可；例如跨项目 agent_message_tool 必须解析明确的目标项目和外部 sourceRef，不能在全局助理运行根查找项目 Agent，或直接复用普通 Agent 的本地消息解析。普通 Agent 工具及默认路由保持原行为。

Launcher 工具尽量保持旧工具名和已接入参数语义，执行 transport 与认证主体显式版本化。平台 PA 专用页面和 HTTP 入口迁走属于对其消费者的破坏性变更；M0 枚举通知深链、模型工具、设置页、桌宠、测试及第三方消费者，逐一迁移，未知消费者不能假定不存在。

源仍未切换时旧契约按旧规则运行；单写者切换后旧 PA 写入口只返回结构化 assistant_moved 与受信任的 Launcher 导航提示，不再承接或转发新的助理业务。通知深链改为 Launcher 受控入口，不能向普通网页下发凭据。迁移窗口按第 12 节关闭后移除旧路由和临时提示；通用平台 API、普通 Agent 工具及插件接口保持原语义。

### 5.4 API 覆盖补齐

| 能力组 | 迁移要求 | 验收重点 |
| --- | --- | --- |
| 助理偏好、用户资料、头像、壁纸、普通设置 | 区分 assistant、operator、project、instance 作用域；复用资产服务 | 一句话修改与原生回读、界面同步、重启后保持 |
| Agent 创建、配置、模型、会话与任务派遣 | 保留字段白名单、revision、工具授权和原生通信 | 正确项目、无重复创建、自定义权限不漂移 |

| 团队、房间与工作流 | 使用 native IDs 和稳定幂等键 | 部分创建、运行中断、成果核验、重复请求不重跑 |

## 6. 操作记录、派遣与失败恢复

### 6.1 最小持久操作关联记录

先复用现有动作的 requestId、跨进程锁、原子写入、原生运行记录和回执，补足全局请求到目标的关联。记录唯一键覆盖 (profileId, targetScope, operationId)，步骤键由父 operationId 与稳定 stepKey 派生；发出有副作用请求前持久保存意图，避免助理崩溃后丢失原键。

必要内容限于 action、参数摘要、目标身份、capabilityRevision、预期 revision、授权引用、native IDs、步骤关联、最后确认时间、回执游标和 evidenceRefs。为恢复保留的有界结构化参数只在私有存储保存；不复制凭据、完整 Prompt、transcript、原生任务正文或另一套可编辑业务对象。

请求是否待发送、已受理或结果未确认，是传输/恢复层的事实；任务 running/completed/failed 等业务状态从原生 Journal、WorkRun 或领域服务读回。保留来源和最后确认时间，不能把投影变成第二个任务状态机。unknown 必须可见，无可证明幂等性时只核验、不重做。

M2 用“发送前、目标写入后回执前、全局记录回执前”三个崩溃边界证明现有持久化原语足够；只有出现不可满足的事务、并发或查询需求时，才以证据决定独立 SQLite 表。无论采用哪种介质，都必须持久去重、跨进程互斥和可恢复；不以精简为由改成纯内存队列，也不引入新工作流引擎。

操作策略按动作声明：

- read_only：允许有界重试。
- native_idempotent：同一原生幂等键重送，目标保证去重。
- cas_write：先读 revision，只有预期版本匹配才写。
- non_replayable：丢失确认后只 reconcile；无法核实时暂停，不自动重送。

本方案不承诺跨进程崩溃下的普遍 exactly-once。只有目标端持久去重或可证明的 CAS 允许安全重试；项目侧进程内锁不能替代跨进程保证。

### 6.2 一句话操作的正常路径

~~~mermaid
sequenceDiagram
    participant U as 用户
    participant A as 常驻助理
    participant E as Electron main
    participant S as 宿主内原生 SDK
    participant P as 项目原生服务
    U->>A: 在项目 A 建团队并运行
    E-->>A: 已登记项目与权限快照
    A->>S: 解析已授权目标
    S->>P: 原生身份和能力握手
    P-->>S: 绑定目标的能力、revision 与授权
    S-->>A: 闭合可执行能力
    A->>A: 保存稳定操作键、必要参数和步骤引用
    A->>S: 受控业务动作与稳定请求键
    S->>P: 原生授权与执行
    P-->>S: 原生对象 ID、运行 ID 和后续回执
    S-->>A: 有界状态与证据
    A->>S: 按原 ID 读回核验
    S->>P: 查询原生对象或回执
    P-->>S: 原生状态
    S-->>A: 核验结果
    A-->>U: 完成结果或明确待处理步骤
~~~

项目业务消息经宿主内原生 SDK 直接通信；可信宿主持有私有项目能力，模型和 renderer 不持有。Electron 保留登记、权限快照与生命周期权威。离线项目需先走 Electron 生命周期桥，在原生身份与能力握手完成后才走上述业务路径；桥尚未完成时明确报告不可用，不转用 Python 启动项目。此路径取代原定“所有项目消息经 Electron 转发”的方案，依据是 2026-10-25 用户明确选择保留原生 SDK。

### 6.3 团队搭建与派遣

一次用户指令生成一个父操作，包含目标、角色、职责、模型、预算、并发上限和成功条件。能用现有模板时自动补全；权限与预算超出当前授权时只集中确认差异。

创建团队、创建成员、绑定角色、启动 native team_run 分别记录稳定步骤和原生 ID。失败时展示已完成步骤，只继续未完成且可证明安全的步骤。只允许补偿本次创建且未被使用的对象；运行中团队或已产生用户成果的对象不得自动删除。

“运行成功”以原生 workflow/WorkRun 与成果验收为准。工具调用结束、普通 Agent Turn 结束、Inbox 投递成功分别只能证明该层完成。全局关联记录只索引原生运行和回执，不创造业务终态。

新派遣以已认证的全局 sourceRef 和稳定 dispatchMessageId 关联目标原生任务，由通用回执入口返回有来源的结果；项目不因此创建 PA Inbox。消息正文仍落目标原生 Session，通用适配只转交必要关联及原生回执，不承担第二套聊天历史。

回执版本明确分开：现有 personalAssistantTask schemaVersion=1、replyToMessageId 和本地 sourceSessionId 仅用于冻结的旧派遣，保留原 v1 来源和目标校验。新派遣使用版本化的外部主体/sourceRef 回执契约，由 M0 冻结版本及 DTO，至少绑定 operationId、dispatchMessageId、全局 sourceRef、目标 project/instance/Agent/Session/Turn 或 runId、任务状态和 evidenceRefs。项目 gateway 根据可信派遣关联与原生来源出具并核验，不能由模型自报身份构成认证。禁止伪造本地 Session、直接向 v1 填全局引用或放宽旧校验来兼容；新旧回执不可串单、重放或互相改变完成状态。

旧派遣保持原发送者、目标、messageId、runId 和原幂等命名空间，迁移时冻结清单及游标。旧创建动作以项目 Agent/Session 派生的去重键不能用新全局身份重新计算后再提交；须保存原键到原生对象的关联，已确认的只核验，unknown 的禁止换键重做。只对清单内在途操作承接旧回执，禁止把现有跨 Inbox 扫描服务变成常驻的 Launcher 观察桥，退出条件见第 7.5 节。

团队自动恢复也纳入迁移：现有 recovery binding 绑定 canonical PA ready、角色策略指纹和到期时间。M0/M5 需要版本化通用主体绑定及撤销语义；不能把全局 ID 填入旧 assistantAgentId，不能因删除旧身份使活跃恢复授权静默失效。旧绑定明确迁移并按新主体重验，或撤销/暂停且报告受影响运行，授权范围和有效期不自动扩大。

### 6.4 故障处理表

| 故障点 | 必须采取的行为 |
| --- | --- |
| 请求尚未发送，项目断开 | 保存步骤并等待该目标恢复；允许用户撤销 |
| 写入发出，响应丢失 | 标记 reconciling，按 operationId/native IDs 查询；无幂等证据不重发 |
| 项目重启或实例 PID 改变 | 重新握手 instanceGeneration、权限和能力，再核对原对象；不把同端口当同实例 |
| 原生停止请求已受理 | 等待目标 turnId/runId 的终态；不能立即报告“已停止” |
| 助理崩溃或电脑异常退出 | 原生 Journal 恢复对话；最小操作关联记录定位原请求/运行并逐项读回 |
| 模型请求中断 | 标记本轮中断；按原生失败恢复/重试语义继续，不重放已完成写入 |
| 授权被撤销、对象 revision 改变 | 立即停止后续步骤，保留结果；按新的差异重新准备 |
| 事件 cursor 失效 | 读取有界原生快照并重建游标；不靠全量高频轮询 |
| 一个项目不可用 | 仅阻塞该项目的依赖步骤；其他项目和助理对话继续 |
| 用户暂停/取消 | 停止新步骤；已开始的原生任务分别请求停止并核对结果 |

## 7. 旧助理数据迁移与单一 owner 切换

### 7.1 迁移前清点

只清点用户选定的已登记项目及实例：canonical PA 身份、直属和历史 Session、设置 revision、模型绑定、ToolPolicy、个人事务插件账本、附件、未完成派遣、持久策略和待审批意图。旧临时批准只作审计，不作为可恢复授权。记录数据解析来源，不扫描全部用户目录。

只有一个合法来源且目标为空时可给出默认推荐。存在多个助理、归档身份、自定义提示或策略冲突、同名不同项目时，展示来源及差异并让用户一次选择；不得按“最新”自动合并。零工具、禁用状态和用户自定义配置保留。

### 7.2 迁移状态机

~~~mermaid
flowchart LR
    I["inventory"] --> P["prepared"]
    P --> Q["source_quiesced"]
    Q --> C["copied"]
    C --> V["verified"]
    V --> S["switched"]
    S --> F["finalized"]
    P --> R["rollback_pending"]
    Q --> R
    C --> R
    V --> R
    S --> R
    R --> K["rolled_back 或需人工恢复"]
~~~

manifest 记录源/目标作用域、数据版本、Journal 水位、文件哈希、资产数量、ownerEpoch、操作阶段和切换指针。相同 migrationId 可安全续跑；失败保留现场，不删除旧文件。

### 7.3 执行步骤

1. **准备**：验证目标为空或属于同一 migrationId，生成 dry-run 差异与备份清单。实施时向用户确认具体来源、影响和可回滚条件；本方案编写不构成活数据切换许可。
2. **冻结旧助理写入**：只暂停选定 PA 的新受理、巡检和唤醒，等待当前 Turn 完成。确需中断时先按原生停止链保存已有记录；不停止其他普通 Agent 和团队。
3. **建立全局身份**：在专属运行根通过原生 bootstrap 创建全局 canonical Agent 和新活动 Session。保留允许迁移的偏好、人物与策略；项目专用工具转换为有作用域的代理能力，任何权限变化必须出现在差异中。
4. **保存历史**：用原生 Journal 水位导出冻结的历史与资产，导入为带 sourceScope 的只读历史 Session。保留原始事件、消息及工具 ID；索引采用来源命名空间避免冲突，不拼接 Journal，不重新执行旧工具调用。原生只读导入适配是 M2 的硬验收前置，不能直接写 ConversationStore 或伪造历史。
5. **恢复上下文**：新活动 Session 可引用迁移摘要和旧历史来源；旧历史中的文本、职责和工具结果作为不可信来源，不能自动成为新的系统权限或指令。
6. **迁移个人事务与设置**：个人待办/日程/目标经插件原生 schema 和事务迁移，保留稳定对象关联、完成/取消状态和删除语义；不搬迁其他 Agent 的账本。资产按白名单、大小、类型、哈希和路径安全规则导入，重建受控 assetRef。
7. **交接未完成派遣与恢复授权**：冻结原来源、dispatchMessageId、目标 Session、native runId、旧去重键和回执水位清单。新 owner 先 reconcile，通过通用回执授权只承接这些任务；不重新派发。旧 recovery binding 按第 6.3 节迁移或明确撤销，记录受影响运行。原 Inbox 要求 active 收件人时，先验证接收地址/观察权交接，再归档身份；不能先归档再期待迟到回复仍能投递。
8. **验证后切换**：确认身份唯一、历史可读、资产可用、设置一致、模型真实可用、未完成操作及绑定可定位。全局切换指针与项目迁移完成标记使用 CAS 和 ownerEpoch fencing；标记不是长期运行模式。
9. **退出平台功能**：平台关闭旧 PA 新受理、规划、初始化、唤醒、巡检和桌宠/页面/设置装配。迁移期旧 URL 只作 assistant_moved 提示，不代理新助理业务。仅当旧任务投递语义确需原记录时短期保留受冻结约束的身份引用，不接受新任务或模型 Turn；完成交接后归档为来源证据并移除适配器。
10. **观察与退役**：至少两个项目重启、一次助理重启、一次真实操作恢复及第 7.5 节全部退出条件通过后标记 finalized。平台不再具备 PA 产品功能或运行装配；旧文件只读保留为备份，删除另行走显式清理。

审批迁移单独处理：acceptAlways 等已经持久化的 ToolPolicy 先核对作用域与权限差异；旧 pending request、Session grant 和进程内 action window 均不得改绑或续期成全局授权。只保留其操作意图和来源引用，旧请求按原生方式终结或过期，新 Session/项目作用域重新 prepare 并依原生策略决定是否需要批准。不能序列化恢复的旧临时状态须明确显示“需要重新确认”，不假定进程退出后仍可读回。

### 7.4 不存在全局原子事务时的处理

全局目录与多个项目不能假定一次原子提交。采用可续跑的逐项目交接：先持久化切换意图、再冻结旧 owner、再激活带新 epoch 的 owner。迁移期旧写入口和旧巡检必须检查冻结状态与 owner epoch；退出后从平台启动链移除，不保留空转的巡检。

尚未开始迁移的来源暂按旧版本运行；已冻结而交接未完成的来源保持恢复只读，不能自动重启旧助理。Launcher 可管理已完成项目授权的目标；不兼容的项目显示所需升级/授权状态，不为它重新部署一套 PA。迁移崩溃后依据 manifest 和真实租约恢复，不凭一个 completed 标志推断所有项目已切换。

| 旧派遣 Inbox、历史与回执适配 | 只按冻结清单收尾；不接受新派遣、自动催办或模型轮次 | 清单全部终态或显式交接，游标追平；验证迟到回执有记录且不会重建 PA、重复派遣后移除适配器 |
| PA 绑定的团队恢复授权 | 转成经重验的通用授权主体，或明确撤销/暂停 | 校验角色策略、原有效期及运行影响；旧 PA 绑定不再被活跃流程引用后才能退出身份 |
| 平台规划师共用的查询、概览及消息能力 | 提取为中性查询/投影服务和独立 planner wrapper，同步其默认工具策略、任务 Prompt 与契约 | 无 PA 的项目中 planner 仍可按原边界读取和派遣；不能整包删除 personal_assistant_project/query 或扩大 planner 权限；旧 PA 工具别名随消费者迁完退出 |
| Session/LLM/Journal、Kernel/Inbox、VUI、个人事务等共享插件及 Companion | 继续由各自 owner 维护，按宿主装配 | 普通 Agent 插件账本、会话与 Companion 回归通过；移走助理自己的实例与 UI，不按文件名批量删除共享能力 |

最终验证平台生产入口不再导入助理专属 service、wrapper 或 patrol；共享模块中的 PA 特例完成移除，文件名迁移不是验收替代。检查 router_registry、lifecycle、工具注册、导航、通知目标、恢复绑定和打包入口；测试覆盖首次创建、升级、重连及迟到事件。关闭条件未满足时报告“迁移/退役未完成”，不能以长期 bridge 模式收口。

## 8. 前端与降低操作成本

Launcher 使用随包资源承载独立助理路由。桌宠和面板连接同一全局 Session，不因项目窗口、前台标签或后端 origin 改变而切换身份。UI 继续使用 VUI 产品 API、现有 recipe 与统一 pane persistence；新增组件先登记 designs，并通过既有守卫。

### 8.1 Launcher 承载完整个人助理

“完整集成”的验收对象是用户能完成的助理场景，不以增加一个跳转按钮或显示形象作为完成。以下既有能力全部在 Launcher 助理面板可达，并复用原页面的业务模块；项目业务编辑器仍可作为成果详情打开。

| 能力 | Launcher 中的交互 | 后端与复用边界 |
| --- | --- | --- |
| 对话、历史、附件和流式输出 | 直接进入同一活动会话；可查原生历史，输入与附件在切换展示时保留 | 复用 ChatCodingRoute/原生 composer 和 Session DTO，不另建聊天状态机或 transcript |
| 平台、项目与实例管理 | 在面板固定目标，查看状态，一句话启动、停止、重启、切换和管理 | Launcher 原生项目注册及命令队列；实际对象与权限仍由目标域校验 |
| Agent 与团队 | 一句话新建、改配置、换模型、建团队并运行，显示分步成果 | 第 4.6 节预设及原生 action/team workflow；创建和运行分别核验 |
| 派遣、进度、审批与恢复 | 在同一操作卡查看进度、批准必要差异、停止任务、继续观察和打开成果 | 复用原生审批、Inbox、WorkRun 与持久回执，不以本地卡片状态替代结果 |
| 个人事务、记忆与偏好 | 待办、日程、目标、对话偏好和可见的记忆管理在面板内完成 | 助理自己的原生插件和设置服务；不读其他 Agent 私有记忆 |
| 模型与助理设置 | 直接选择有效模型、诊断连接，修改人物、主动程度、通知和形象 | 复用原生配置 DTO、校验和凭据入口，不复制 Provider 目录 |
| 用户资料、头像、壁纸和普通平台设置 | 自然语言完成，必要时在面板内展示结构化选择及结果 | 使用现有受控动作及资产服务；明确 operator/project/assistant 作用域 |
| 电脑操作与能力说明 | 在面板内发现能力、处理原生同意、查看受控操作及未支持原因 | 保留现有观察/执行授权；不向 Launcher renderer 开放任意系统命令 |

“全部既有功能迁移”与“全部 HTTP API 开放”分别统计。第 2.1 节已接入能力必须零遗漏，尚未支持的 API 按第 5.4 节分类；迁移不能把受限或内部 API 自动变成任意调用工具。

Launcher 主界面、桌面形象和托盘都唤起同一助理面板。平台不保留助理入口、嵌入视图或设置页；迁移窗口内历史深链只作受控导航提示。Launcher 内不同展示形态复用同一功能模块和 domain transport；项目上下文由明确目标参数传入，不重新初始化助理。不得通过伪装成 Workbench 窗口放宽原有 IPC 权限；为 Launcher/助理窗口新增窄的、校验角色和来源的专用方法。

### 8.2 打开即显示的桌面形象

首版复用现有 DesktopPetCharacter、大飞鱼/小洛 renderer、透明窗口、边界钳制与展开聊天能力。形象资产随助理包交付，与页面和配置一起脱离项目 origin；启动时无需先下载模型、启动项目或成功连接 LLM。缺模型时形象仍可显示，并提供连接修复入口。

| 用户动作或事件 | 预期行为 |
| --- | --- |
| 首次安装或用户主动打开 Launcher/个人助理 | 默认启动已启用的助理并显示一个收起态形象；已有窗口时复用，不重复创建。明确禁用助理的设置仍受尊重 |
| 点击形象或托盘“打开助理” | 一步唤起完整面板并定位当前会话；只在用户主动操作时将输入焦点交给面板 |
| 后台自启、通知和恢复连接 | 遵循明确的自启/可见性偏好；不抢焦点、不突然展开面板；事件不会把刚隐藏的形象重新弹出 |
| 关闭聊天区 | 收起聊天；保留形象和后台服务，未发送输入不丢失 |
| 隐藏形象 | 只隐藏展示；托盘/Launcher 一步恢复，进行中操作继续 |
| 拖动形象、调整大小、切换屏幕 | 复用窗口位置与边界 helper；屏幕移除、DPI/任务栏变化后仍在可见工作区；尺寸和位置不写回项目配置 |
| 形象资产加载失败 | 使用随包的轻量占位形象及恢复入口，不让聊天、任务或设置不可用 |

透明的非交互区域必须允许鼠标穿透；拖动区域、菜单和聊天区保留命中测试。默认采用包围形象的有限窗口，不照搬跨全部显示器的全屏透明覆盖层。显示使用不抢焦点的原生方式，不能为展示常驻而持续获取鼠标或键盘焦点。

动画只投影权威事件：受理/模型输出、受控动作执行、等待用户、等待项目、失败和有证据的完成分别展示；idle/ready 只能表示等待或就绪，不能显示为任务成功。投影关联 sessionId、turnId、operationId 及原生来源，过期回执不覆盖当前状态；不为形象改写普通 Session 或统一各领域状态枚举。

Live2D、VRM、口型、语音输入输出和复杂动作作为可选增强，采用 renderer 适配边界。它们不成为本次迁移的必装依赖，也不另建对话、记忆或权限内核；任何角色资产和 SDK 的许可证分别核对。

### 8.3 关闭、常驻与退出

| 操作 | 窗口与服务生命周期 |
| --- | --- |
| 关闭项目工作台 | 关闭该窗口，项目是否停止按现有规则；常驻助理和桌面形象独立 |
| 关闭 Launcher 主窗口或助理面板 | 隐藏对应界面，托盘与助理运行时继续；首次发生时用简短提示解释，无需每次确认 |
| 关闭桌面形象 | 隐藏形象，不清空会话、不停止派遣、不终止服务；后续明确打开可恢复 |
| 隐藏全部窗口 | 托盘仍可恢复；窗口数量为零不能自动触发退出或清除服务 owner |
| 明确退出 Launcher | 按第 9.1 节停止新受理、保存并关停自己的服务；不自动终止项目中已派出的任务 |

开机自启是独立的显式用户偏好，不因“常驻”自动开启。用户本轮确认的是打开 Launcher 后具备完整助理与形象；本机后台安装、系统服务与开机常驻不在授权范围内。

### 8.4 共享交互与最小改造面

- 保留当前输入、流式输出、附件、偏好和待审批操作意图；审批是否有效按当前 scope 与原生状态判断，不能搬用旧临时批准。窗口隐藏只降低展示更新频率，不关闭后台执行。
- 操作卡清楚展示项目/实例、实际作用域、变更摘要、当前步骤与成功证据。共享用户名、模型或壁纸变更标明影响所有使用该配置源的实例。
- 常规已授权操作自动完成；只有有意义的目标歧义或权限差异才集中询问，不要求用户逐项进入设置页。
- 断线显示最后确认时间和等待对象；不把缓存状态绘制为实时状态。
- 提供“继续观察、停止任务、打开成果、修复连接”的受控动作；取消观察与停止任务使用不同文案。
- 偏好通过 revision 和成功事件更新，窗口重新显示时做一次读回；不让旧异步响应覆盖新设置。
- 工作台不再承载个人助理。普通网页不获取全局服务凭据；迁移期 assistant_moved 页面不启动助理后端或承接业务，退出窗口后移除。平台业务自己的任务、团队和设置 UI 继续服务普通用户与 Agent。

本地源码落点已经核对：

| 现有实现 | 直接复用 | 必要适配 |
| --- | --- | --- |
| [PersonalAssistantRoute](../../web/src/routes/PersonalAssistantRoute.tsx)、personalAssistant/ | 全功能模块、偏好、概览、事务和操作 UI | 迁入 Launcher 唯一产品入口，移除 Workbench 装配依赖和旧路由；注入助理 transport 与目标作用域 |
| [DesktopAssistantRoute](../../web/src/routes/desktopPet/DesktopAssistantRoute.tsx) 与 DesktopPetCharacter | 收起形象、展开聊天、同一身份和活动投影 | 改用全局助理连接和随包资产；完整管理能力由同一面板承接，不塞入另一套概览 |
| [petWindow](../../desktop/electron/src/windows/petWindow.ts)、petWindowBounds | 透明安全窗口、位置恢复、屏幕边界 | URL 不再从 Workbench origin 派生；打开时自动显示；关闭改为隐藏 |
| [petSettingsControl](../../desktop/electron/src/windows/petSettingsControl.ts)、preload/IPC | 窗口请求的集中校验与单实例控制 | 增加独立助理窗口角色与窄方法；移除由某个项目 origin 独占形象的语义，不放开通用控制接口 |
| [electronWindowProvider](../../desktop/electron/src/windows/electronWindowProvider.ts) 与 Launcher 随包协议 | 窗口复用、托盘存活、资源协议与安全默认值 | 固定助理独立资源和生命周期 owner，工作台启停不影响助理 |

先完成“无项目启动 Launcher → 显示已有形象 → 打开完整面板 → 一次真实对话”的切片，再迁移全部功能。可复用内容以现有模块为单位提取，不重新实现聊天页、角色引擎或一套 Launcher 专用设置页。

助理 UI 与共享 ChatCoding/VUI 源码可以按构建入口复用；平台构建不注册 PA 路由，Launcher 构建不拉入无关工作台业务。模块复用不意味着两个产品入口长期并存，也不把普通 Agent 的聊天能力一起移出平台。

本方案不规定最终视觉布局；可见 UI 改动实施前按项目现行 UI 契约完成预览或明确复用路径，禁止临时引入第二套设计系统。

## 9. 生命周期、发布与运行恢复

### 9.1 监督与关停

Electron 启动后按用户启用状态启动助理，关闭工作台不退出服务。项目回收列表、工作台 Job 和 runtime-manager registered PIDs 中不包含助理。助理有自己的租约、日志、健康探测和有界崩溃退避；建议初始策略为 1/2/4 秒退避，10 分钟内超过 3 次异常退出转为 degraded，由恢复入口处理，避免无限拉起。具体时间为待测初始值。

退出 Launcher 时先关闭新对话与新动作准入，保存原生 Session 和操作记录，取消订阅并有界关停助理。取消退出不得提前停止服务；退出超时需说明未确认状态。助理退出不自动停止项目中已经派出的任务，除非用户明确请求停止这些任务。

### 9.2 构建与升级

构建产物包含 Electron、助理代码闭包、锁定 Python 依赖、独立 UI 资源与协议清单。release provenance/freshness 必须覆盖这些内容，不能只比较 Electron tree hash。运行包不从活 checkout import，产品启动不现场 pip install，也不临时回退项目 .venv。

升级采用 prepare、quiesce、switch、verify、commit：先检查协议/数据版本兼容，旧 owner 保存检查点并退出，新包验证后接管；失败保持可回到旧包。最少保留一个匹配数据 schema 的可用旧包。schema 升级优先可扩展变更，无法逆向读取的数据升级必须先形成独立迁移与备份方案。

Launcher 自身退出/更新仍会中断助理进程。本方案保证持久化恢复，不承诺跨 Launcher 退出的连续 TCP、模型请求或运行内存。

### 9.3 可观测性与成本

建立独立 assistant runtime scene，关联 profileId、operationId、projectId、instanceId、sessionId、turnId、native runId、协议与 release。默认日志只记有界元数据、错误码和证据引用；用户消息与原生对话仍按 Session 原有隐私与删除规则管理。

空闲不发模型请求；项目事件、用户消息和明确到期事项才触发处理。复用现有催办次数、冷却和每小时唤醒限制；全局调度再加总预算，防止多个项目各自满足额度却导致整体放大。低频健康探测只面向已连接或有待恢复操作的实例。

## 12. 切换、回滚与停止条件

### 12.1 有限迁移窗口与最终状态

最终只有 Launcher 个人助理，不提供 legacy、bridge、resident 三种长期产品模式。迁移工具可以记录 prepared/frozen/switched/retired 等阶段和临时开关，但这些只用于单写者交接与故障恢复，不保留多套人物、配置、规划器或运行入口。

先在隔离数据完成 M1/M3 切片，再迁移选定来源、逐项目核验授权和旧任务。M0 为旧消费者逐项登记 owner、目标发布范围和退出条件；切换后旧 PA 入口只提示已迁移。第 7.5 节清单、旧入口调用清零、旧任务/恢复绑定交接、历史/资产与回滚演练全部闭合后移除临时适配。超出登记窗口时报告具体未完成项，不将兼容代码改成永久运行模式；时间到期本身不能删除活数据或丢弃迟到回执。

平台版本过旧、协议不匹配或授权未完成时，Launcher 显示目标不可操作及所需恢复步骤，其余目标和对话继续。不能为兼容旧项目自动重新部署项目内 PA。退役完成后的正常升级/回滚只面向 Launcher 助理包及其兼容数据，平台不重新获得个人助理功能。

### 12.2 回滚规则

- **尚未切换**：封存未激活目标，核对源冻结状态后可恢复迁移前准入；源数据不变。这是迁移失败恢复，不是最终双端支持。
- **迁移窗口内已切换但无新业务写入**：优先退回已验证的 Launcher 助理包；确需回到来源时，通过显式迁移回滚核对水位、epoch 和消费者，再恢复唯一源 owner，保留全局快照并标记迁移未完成。
- **已产生新对话或配置**：先冻结全局 owner，保存其原生历史和差异；不把旧文件覆盖回新状态。全局新对话保留为只读历史；受支持的设置经原生事务做有版本检查的反向迁移，冲突集中交由用户选择。
- **个人事务账本已有增改删**：同时冻结全局与旧项目提醒 collector，按稳定对象 ID、删除标记、完成/取消状态、源 revision 和已消费提醒游标，执行插件原生反向迁移并核验。只有最新账本及提醒游标的唯一 owner 确认后才恢复写入和提醒，不能重新启用旧快照。无法证明回迁完整时保持 rollback_pending 和最新账本的只读恢复入口，不启动旧 PA 的个人事务写入或提醒；明确说明回滚未完成。
- **已派出新任务**：原生项目任务继续存在，操作关联记录和回执游标保留；回滚只改变观察 owner，不能重新派发。使用兼容的 Launcher 只读恢复入口观察至交接或终态，不在平台重建 PA。
- **新旧包不兼容**：退到已验证匹配 schema 的包；无法证明兼容时保持恢复模式，不能强行启动旧写入者。
- **平台 PA 已退役**：只回退兼容的 Launcher 助理版本；不自动恢复旧平台页面、巡检、身份或 API。无法处理的数据保持可读恢复并报告 blocker，恢复平台旧产品必须另立明确任务。
- **回滚失败或身份不明**：维持单写者冻结状态和可读证据，明确标记 rollback_pending；不自动清空数据或重新初始化。

### 12.3 必须停止推进的条件

出现跨项目误操作、重复业务写入、旧自定义策略被放宽、双 owner、凭据进入 renderer/Prompt、普通 Session 行为漂移、历史校验失败、无法恢复的 schema 变化或可见控制台弹窗时，停止切默认和发布。先隔离受影响入口、保留现场、修复并补对应证据；不能用“主流程可用”覆盖这些缺口。

## 13. 复用依据与关键风险

### 13.1 复用决策

直接复用现有 Electron 单例和窄 IPC、无控制台原语、原生 Session/Journal、动作 schema、授权规则/DTO、配置事务、Kernel/Inbox、团队工作流和 VUI。对宿主、外部主体动作授权、原生历史导入及操作恢复进行适配，不另建 Agent 框架；“复用授权规则”不等于直接复用缺 Agent runtime 时默认放行的旧工具入口。

外部机制仅用于核对边界，当前方案不新增相关依赖：

| 官方来源 | 借鉴点 | 本项目边界 |
| --- | --- | --- |
| [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security/) | IPC sender 校验、隔离 renderer 权限 | 使用现有 main/preload 边界，不给面板任意本机控制接口 |
| [OpenAI Agents SDK 人工审批与恢复](https://openai.github.io/openai-agents-python/human_in_the_loop/) | 服务端保存审批中断和可恢复状态 | 继续使用 Vibelution ToolPolicy/原生审批，不替换会话执行器 |
| [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) | 区分会话检查点与跨会话持久数据 | 继续使用 Journal 和独立操作元数据；检查点本身不提供副作用去重或项目权限 |

### 13.2 主要风险及关闭方式

| 风险 | 必须关闭的证据 |
| --- | --- |
| 同进程切换项目全局根造成串写 | 固定单运行根；两项目并行负例和普通 Session 回归 |
| 只移界面，仍加载项目代码/资源 | 独立运行包检查与原生桌面停项目验收 |
| 无项目 PA 后落入 system_context 或绕过 ACL | 外部主体授权门默认拒绝、作用域交集、私有知识/Inbox 与伪造身份/参数/批准负例 |
| 项目重启后重复写入 | 持久化操作键、目标去重/CAS、每一故障边界注入 |
| 多个助理/历史/设置发生冲突 | 单来源选择、dry-run、原生只读历史与完整哈希、逐项目 owner 交接 |

| 平台残留 PA 或误删共享查询/消息能力 | 平台退役静态检查及无 PA 项目冷启动；planner、普通 Agent、通知和 Companion 回归 |
| 先归档旧身份导致回执/恢复绑定失效 | 冻结清单、接收地址及权限交接、旧绑定迁移/撤销、迟到回执故障验证 |

## 14. 维护成本与防重复开发约束

### 14.1 源码、宿主与发布责任

独立进程、数据根和运行包是稳定性边界；源码继续放在同一仓库，用共享模块与构建清单复用。首版不拆独立仓库，不把现有代码复制为 launcher_session、launcher_llm 或另一套 Agent SDK，也不为“共享”而把整个平台核心改成可动态切根的通用框架。

| 层次 | 唯一维护责任 | 变更后的验证范围 |
| --- | --- | --- |
| Launcher 助理产品 | 一份人物/偏好/事务/派遣 UI、工具装配、全局调度与桌面形象 | 对应助理 UI/真实行为、窗口生命周期；无关普通项目页面不因助理样式改动而重写 |
| 原生共享基础 | 一份 Session/LLM/Journal、配置事务、工具规则、消息和 VUI 源码 | 改动影响普通 Agent 时，普通会话与独立助理宿主都做对应回归；禁止两个分支版本分别修复 |
| 项目通用业务 | 领域 service、动作 schema、对象 ACL、原生运行与回执权威 | 原生业务及外部主体调用负例；页面、助理能力说明与客户端从相同 schema/能力版本投影 |
| 最小连接适配 | 一份项目解析、握手、外部主体授权、typed transport、事件/回执映射 | 错目标、撤销、断线、重复提交、游标过期；不增加每项目 PA 进程或一套聊天状态 |
| 构建与版本 | 集中依赖锁、代码闭包、协议兼容范围和 release manifest | 实际 Windows 包、无控制台、冷启动与回退；不在启动时安装依赖或引用活 checkout |
| 迁移专用工具 | 一次性导入、冻结清单、旧回执/深链适配和退出检查 | dry-run/resume/rollback、旧绑定与迟到回执；退出后从产品运行链移除，不成为常驻成本 |

保持既有 HTTP/SSE DTO 和事件形状，私有通道只做必要 bootstrap 与窄项目命令；不再增加一套承载聊天正文的自定义协议。版本兼容策略由一份共享契约和发布清单定义，避免每个窗口或项目分别实现降级规则。助理 UI 独立变更不强制改动普通项目业务；共享核心或协议变化才扩大验证面。

### 14.2 实施成本口径与收敛顺序

当前静态粗预算仍为完整迁移约 20–35 工程人日，假设由熟悉仓库的工程人员完成、原生代码大部可复用，并包含既有功能迁移、历史/在途任务处理、平台退役及相关真实模型/桌面/故障验收。此前 12–20 人日仅对应最小可用阶段，不能作为完整退役承诺；人日不是自然日，也不是 Agent 自动执行时间。

预算不包含剩余业务 API 新增、Live2D/语音、新的多端产品及远端发布。活数据规模、旧消费者清单和外部主体对原生 ACL/派遣/恢复绑定的适配尚未完成运行证明，是主要不确定项；若 M1/M3 切片证实需要改动普通核心或不可复用授权能力，需据实重估，不能靠放宽身份检查保持原预算。

实施先后顺序用于尽早暴露成本：

1. M0 列明唯一 owner、共享依赖、旧消费者/退役项，以及新调用主体和旧回执/恢复绑定契约。
2. 优先完成 M1/M3 的无项目 PA 切片；证明独立宿主、最终授权、派遣、回执与去重后，再搬完整界面和活数据。
3. 迁移既有模块，先保护共享查询、规划师与普通 Agent，再解除平台 PA 装配；不先复制整套平台再逐步关闭。
4. M6 同时关闭平台产品入口和有范围的临时适配，M7 验证唯一归属；退役是完成条件，不单独留作无期限后续事项。

### 14.3 持续维护成本的判断与验收

最终维护成本判断为中等：助理功能只维护一处，但独立包、跨进程授权与断线恢复需要持续维护。相对于平台内单宿主会新增这些边界成本；相对于 Launcher 与平台长期共存，减少重复 UI/配置/初始化、每项目 PA 和多运行模式的维护面。现无维护工时与故障频率数据，不承诺固定月度人日或节省百分比。

以以下可检查条件控制后续成本：

- 新助理功能只改唯一产品装配；共享业务动作只保留一份 schema/领域实现，能力文档与工具索引自动投影，语义授权和业务验收仍显式维护。
- 构建依赖闭包、协议范围、迁移 schema 和实际包 provenance 集中维护；禁止 UI、Python 包和项目客户端各自猜版本。
- 平台没有 PA 产品路由、默认身份创建、巡检或隐藏 bridge；普通 Agent、规划师、通知、插件和 Companion 有对应回归。
- 临时迁移适配有未关闭操作清单和明确 owner；全部交接后真实关闭，不以“以后也许有用”为由进入正常运行链。
- 一次请求在断线与重启后仍指向同一原生对象；不以新增全局任务引擎、第二份 transcript 或复制原生对象来解决恢复。

实施完成后的证据必须同时证明“Launcher 功能完整”和“平台个人助理功能已退出”。阶段性源码或模型验收不能替代这个完成条件。

资源和配置仍由原owner写入：新通道只复用既有头像/背景store、Windows namespace lease、operator config transaction；随机名排他创建防覆盖，目录lease的显式child-write模式继续禁止目录重命名且不改变普通source reader默认。组合测试发现并修复了theme多余字段投影与头像逻辑前缀错误，新增真实Python宿主/main/图片服务导入、取消和重启读回；使用虚构身份与chooser/renderer seam，没有真实模型。新加载源码页面已确认明暗切换、刷新保留、同来源另一页面同步、图片自动替换/清空，截图待完整ConversationView稳定后取证。原生文件选择框尚未真人交互验收。DeepSeek继续等待额度确认，正式安装/运行与旧个人助理不变。

后续API不能用旧会话getter名称直接接通：session_parameters_get会经过ensure/repair，并且有效推理选项还依赖verified catalog与runtime/env配置；已做隔离反例，暂未用历史compiled值或仅TOML值冒充旧语义。下一片优先接通明确原生owner的Agent归档，复用审批、版本CAS和原请求回执；其余语义API、旧授权/历史/在途交接和最终新包真实模型验收继续保留。

Agent归档现已接通动态说明、SDK、独立agents:archive权限和原生逐次审批；严格configRevision CAS位于canonical archive lock内，通过后直接委托现有归档/Session封存owner，不预写metadata。受保护、团队/Companion、损坏身份、忙碌关联会话与过期版本拒绝，unknown或重启后只读原回执、不重放归档。完成回执保存首次确认的历史状态。旧无scopes授权冻结原八项、已有九项原样保持、新主体显式请求十项，绑定回包必须精确相符；不静默给旧主体加权。真实Temp普通配置Agent及其Session封存、忙碌/保护/CAS反例、SDK授权和回执回归均通过，独立复审无阻断。其余语义API、有效参数只读owner、显式旧授权升级、历史/在途数据交接和最终新包DeepSeek验收仍未完成，平台旧助理继续保留。

最终自审另发现Agent旧getter隐式repair及sandbox路径ensure/seed，冻结候选因此未合入。新归档已改为专用existing-only authority adapter，新适配器的身份/CAS检查与unknown回读不走get_agent/load_state/load_agent_record；进入原生事务前先existing-only预读，缺authority立即拒绝，锁内再重载；registry/roster按限长strict JSON读，Companion store也使用同一不初始化resolver，缺authority拒绝。头像回执只报告persisted选择，不hydrate当前默认logo。新增哨兵先复现旧getter进入admission，再验证stale拒绝、unknown重启回读及开发沙箱缺authority都不写/复制/初始化。桌面全量出现游移超时，调查确认默认容量为15个fork；资源争用是优先假设，现独立将Vitest文件并发限制为4，未改变超时、断言、隔离或selector，完整检查仍须重新通过。

### 2026-10-26：剩余查询与旧授权交接增量

### 2026-10-26：窗口响应与后台清退分开确认

迁盘后的完整合入检查在既有原生 fast-close 用例出现资源清退超时；未改动 main 的临时对照同样复现。诊断确认 Job accounting 归零不等于 root process wait、输出 drain 或 TCP listener 已完成，不能把这些资源强行记为关闭。用户随后明确选择窗口及时关闭、Launcher 后台持续回收并显示未完成，决策见 ADR 0014。

### 2026-10-27：退出运行时修复与旧派遣交接预览

展开会话后的退出异常已在无主进程 Inspector、无 Chromium 调试端口的临时完整应用复现：调用原托盘退出回调，宿主停止后 Electron 42.5.0 两次以 `0x80000003` 退出。相同应用、原生 Job 插件和测试回调仅替换官方运行时后，42.11.18 与 43.8.3 各三次正常退出。两份崩溃 dump 的原生线程链一致，故障位于 Electron 最终退出阶段；具体 Node/V8 函数归因仍以无 PDB 的对应推断表述。官方修复 [Electron #52956](https://github.com/electron/electron/pull/52956) 与 [42 系列回补](https://releases.electronjs.org/pr/53014) 记录了关闭后延迟任务触碰旧句柄的问题，后者从 42.10.0 发布。

本片将依赖固定为仍受支持的 Electron 43.8.3，复用上游修复，不增加应用层销毁窗口或延迟退出补丁。打包 owner 同时验证安装包版本、真实 distribution 版本与项目精确声明版本一致，防止升级声明后仍复制旧 runtime。官方 ZIP SHA256 与 npm 完整性均已核验，开发依赖仅在任务环境更新；最终重新构建包的验收另行记录，正式程序及配置不自动更新。

旧授权继续复用既有显式升级、持久化证明及重启后的只读回执恢复；原 8/9/10 项授权不自动扩大。新增 `assistant_migration_inventory.py --project <source> --handoff-preview <explicit-pa-agent-id>` 只读预览：复用纯身份裁决和旧派遣报告规则，扫描明确来源中 active/archived Agent 的默认 inbox，记录来源指纹、旧 message ID、双方 Session 与严格关联的回执；正常用户/系统消息允许空来源，不作为任务报告。错误路由、重复 ID、来源变化、损坏、限额及自定义路径均显式不完整，报告不导出正文或 evidence 原文。迟到回执可在重跑后被读取，不创建或重放任务。
