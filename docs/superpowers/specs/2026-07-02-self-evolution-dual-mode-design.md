# 自进化双模式设计

## 背景

当前自进化页面已经收敛成两个核心阶段：自进化与审批。现有后端也同时存在两条相关能力：一条是把自进化写入目标委托到受审查的 worktree 运行，另一条是有界自进化运行。新的产品目标不是恢复旧链路，而是在当前自进化页面上明确提供两种不同语义的模式。

两种模式必须解决不同问题：

- 隔离开发模式用于真实改进项目。Agent 可以在独立 worktree 中开发，但必须经过审查 Agent 与用户审批后才允许合入。
- 自主观察模式用于观察 Agent 的思考质量与行为倾向。Agent 默认没有任何工具，也不能申请工具、读取文件、运行命令、搜索、修改代码或生成可合入候选。

## 目标

1. 让用户在启动自进化前明确选择运行模式，避免“会不会自己改代码”的语义混乱。
2. 复用现有会话展示链路，让两种模式的实时输出都以 Agent 会话形式呈现。
3. 隔离开发模式形成完整闭环：开 worktree、开发、审查、用户审批、合入或丢弃。
4. 自主观察模式形成纯观察闭环：设定目标与时长、无工具运行、实时观察、自动结束、生成观察报告。
5. 自主观察模式的提示词必须阻止虚假执行叙述，要求 Agent 明确区分思考、假设、未验证项和未来需要的证据。

## 非目标

- 本轮不设计自主观察模式的工具申请、动态加工具或临时授权。
- 本轮不允许自主观察模式写入代码、生成 patch、创建 worktree、执行测试或触发合入。
- 本轮不重新设计 Agent 管理中心。
- 本轮不把两个模式混成一个“高级选项”入口；它们是不同运行语义。
- 本轮不让系统自动合入 main。合入仍必须是用户审批后的显式动作。

## 模式一：隔离开发模式

隔离开发模式是默认推荐模式，适合用户希望 Vibelution 真实改进自身时使用。

### 用户可见行为

用户输入一个开发目标后，系统创建独立 worktree 与任务分支。开发 Agent 在该 worktree 中完成一次开发任务，输出代码 diff、验证结果和开发总结。开发结束后，审查 Agent 分析变更范围、测试证据、风险、回滚路径和是否建议合入。页面最后进入用户审批状态，用户可以选择批准合入、拒绝丢弃、保留 worktree 继续人工排查或终止运行。

### 流程

1. 启动：用户选择隔离开发模式并填写目标。
2. 准备：后端创建 worktree run，记录 sourceTrack 为 self_evolution，保留 selfEvolutionGoal 与 reviewReason。
3. 开发：开发 Agent 复用对话链路执行开发任务，实时输出显示在会话视图。
4. 审查：审查 Agent 读取开发产物和验证证据，生成审查结论。
5. 审批：用户查看开发摘要、审查结论、变更文件、测试结果和风险后决定是否合入。
6. 收口：合入成功、丢弃、保留 worktree 或终止都必须写入运行记录。

### 权限边界

开发只能发生在隔离 worktree 中。运行不能直接修改主线 main。审查 Agent 不负责自动合入。用户审批是唯一可以进入合入动作的入口。

## 模式二：自主观察模式

自主观察模式是无工具纯观察模式，适合用户想观察 Agent 自主思考过程、目标理解能力和自我约束能力时使用。

### 用户可见行为

用户输入观察目标并设置运行时长。系统启动一个观察 run，Agent 在无工具环境中持续输出思考轨迹。到达时长上限或用户手动终止后，系统生成观察报告。报告描述 Agent 如何理解目标、如何拆解问题、暴露了哪些假设、承认了哪些无法验证的内容、未来如果允许工具需要收集哪些证据。

### 强制限制

- 允许工具数为 0。
- 不显示工具申请入口。
- 不支持动态添加工具。
- 不创建 worktree。
- 不读写文件。
- 不运行命令。
- 不访问网络或搜索。
- 不修改配置、记忆、Agent、会话、团队或运行状态。
- 不生成可合入候选，不进入合入审批。

### 结束条件

自主观察 run 在以下任一条件满足时结束：

- 到达用户设置的运行时长。
- 用户点击终止。
- 后端检测到模式边界被违反，例如 Agent 声称已经执行工具、读取文件或完成验证。
- 运行链路异常，无法继续产生可追踪输出。

## 自主观察提示词契约

自主观察模式需要专用系统提示词。提示词要把 Agent 的身份限定为“无工具观察沙盒中的自进化观察 Agent”，并明确以下规则：

1. 你没有任何工具。
2. 你不能声称已经读取、搜索、运行、验证、修改、提交、合并或调用外部能力。
3. 你可以做的是理解目标、提出假设、分解可能路径、识别风险、描述未来需要的证据。
4. 每段输出都应区分已知信息、推测、无法验证项和下一步如果有工具才会做的事。
5. 你必须在需要证据时承认限制，而不是编造结果。
6. 你不能请求工具授权，因为本模式本阶段不支持工具申请。
7. 你的输出目标是帮助用户观察你的思维质量，而不是完成开发。

推荐输出结构：

```text
当前理解：
可观察推理：
关键假设：
无法验证：
如果未来允许工具，需要的证据：
下一段观察重点：
```

结束报告结构：

```text
观察目标：
运行时长：
思考路径摘要：
主要假设：
无法验证清单：
风险与自我约束表现：
未来可执行实验建议：
```

## 前端设计

自进化页面顶部增加模式选择区，两个选项并列：

- 隔离开发
- 自主观察

选择隔离开发时，页面展示目标输入、启动隔离 worktree、开发会话、审查结论与用户审批区域。

选择自主观察时，页面展示观察目标、运行时长、启动观察、实时思考轨迹、终止按钮和观察报告区域。该模式不展示工具列表、工具申请、worktree 文件、diff、合入、丢弃候选或审查 Agent 卡片。

两种模式都保留稳定的运行状态和当前输出。历史记录应进入专门历史区域，不应覆盖新一轮当前状态。

## 后端与 API 设计

隔离开发模式继续复用现有自进化 worktree 入口，并明确在 payload 中携带 mode 语义，例如 `selfDevelopmentMode=isolated_development`。后端应把该运行标记为 self_evolution 来源的 worktree run，并保留审查与审批动作。

自主观察模式应使用独立运行类型，建议命名为 `self_observation_run` 或在现有 self-evolution run 中显式存储 `selfMode=observation`。该运行不应持有写入 lease，不应进入 worktree run 列表，不应触发 risky write delegation。它只需要存储目标、时长、状态、会话 id、观察输出、结束报告和边界违规原因。

建议 API：

- `POST /api/evolution/self/worktree-runs`：隔离开发模式。
- `POST /api/evolution/self/observation-runs`：自主观察模式。
- `GET /api/evolution/self/observation-runs/{runId}`：读取观察 run。
- `GET /api/evolution/self/observation-runs/{runId}/events`：观察 run 实时事件。
- `POST /api/evolution/self/observation-runs/{runId}/actions`：终止观察 run。

如果实施阶段决定复用现有 self run API，也必须保持 DTO 中的模式字段清晰，并让前端和历史记录能区分两种 run。

## 数据投影

自进化页面需要能同时投影两种当前状态：

- `selfDevelopmentActiveRun`：隔离开发模式当前 worktree run。
- `selfObservationActiveRun`：自主观察模式当前观察 run。

历史区域应分开：

- 开发候选历史：包含 worktree、diff、审查、审批、合入/丢弃结果。
- 观察实验历史：包含观察目标、时长、输出摘要、结束报告、边界违规状态。

当前页面只展示当前运行，不把旧运行结果冒充为当前状态。

## 日志与证据

隔离开发模式继续记录 worktree run 生命周期、审查结果、审批动作、合入或丢弃动作。

自主观察模式需要记录：

- 观察 run 启动。
- 目标和时长。
- 会话创建。
- 定时结束或用户终止。
- 观察报告生成。
- 边界违规检测，例如声称执行工具或声称读取文件。

日志不得写入完整提示词、长输出、密钥、完整 diff 或未截断模型响应。记录稳定 id、状态、时长、摘要和违规类别即可。

## 错误处理

隔离开发模式错误应按 worktree run 错误路径展示，包括创建 worktree 失败、开发失败、审查失败、测试失败、合入失败和终止失败。

自主观察模式错误应避免显示“开发失败”语义。推荐错误分类：

- `duration_invalid`：运行时长非法。
- `observation_already_running`：已有观察 run 正在运行。
- `session_start_failed`：观察会话启动失败。
- `boundary_violation`：Agent 输出违反无工具观察约束。
- `operator_terminated`：用户终止。
- `runtime_error`：运行链路异常。

## 测试计划

后端测试：

- 隔离开发模式仍进入 worktree run，并保留审查与审批动作。
- 自主观察模式不会创建 worktree。
- 自主观察模式不会持有写入 lease。
- 自主观察模式 DTO 中 allowedTools 为空。
- 自主观察模式到达时长后自动结束。
- 自主观察模式终止动作可用。
- 自主观察模式边界违规会进入明确状态。

前端测试：

- 自进化页显示两个模式入口。
- 隔离开发模式显示 worktree、审查、审批相关区域。
- 自主观察模式不显示工具申请、worktree 文件、diff、合入、审查 Agent 卡片。
- 自主观察模式显示运行时长、实时思考轨迹、终止按钮和观察报告。
- 模式切换不把历史运行结果显示为当前运行。

提示词测试：

- 自主观察提示词包含无工具约束。
- 自主观察提示词禁止声称执行、读取、搜索、验证和修改。
- 自主观察提示词禁止工具申请。
- 自主观察提示词要求输出无法验证项和未来证据需求。

构建与回归：

- 前端变更后运行相关 route/static/layout 测试与 `npm --prefix web run build`。
- 后端变更后运行 self-evolution、worktree evolution、web evolution route 相关测试。

## 发布与刷新

该功能会影响前端可见页面、后端运行 API、会话链路和 runtime-scene 证据。实施完成后需要 Launcher 刷新后才能做真实页面验收。刷新前必须检查 active-work guard，避免中断正在运行的任务。

## 版本影响

该改动属于自进化产品行为增强，建议作为 patch 版本中的功能改进记录，不需要单独改变配置文件版本语义。是否更新 `VERSION` 和 `CHANGELOG.md` 由主线发布节奏决定，普通任务分支不直接修改。

## 验收标准

设计实现后，用户应能清楚回答：

- 我现在启动的是会开发的自进化，还是只观察的自进化。
- 隔离开发模式的改动是否经过审查，是否等待我审批。
- 自主观察模式是否真的没有工具、没有 worktree、不会改代码。
- 自主观察 Agent 的输出哪些是推理，哪些是假设，哪些没有被验证。
- 旧历史不会污染新一轮当前状态。
