# Vibelution 开发架构地图

直接打开同目录的 `index.html`。它是离线单文件：无需服务器、安装依赖、联网或启动 Vibelution。首页先看“界面 → 请求 → Session 调度 → Agent 回合 → 模型与工具”，再看下方的记录与回显。点击节点展开技术详情，点击箭头查看关系；按 Escape 清除高亮。

建议从左侧的“系统如何运转”“一条消息的执行过程”“Agent 如何调用模型”“数据在哪里，谁是权威”开始。复杂视图先展示主流程，“完整实现”保留调度适配、上下文、授权和存储等原图节点。较长流程在右侧转入下一行，序号和上方导航只帮助阅读，不额外表示执行或调用顺序。

节点详情按输入、处理、输出、边界组织；先进入相关业务流程，再展开源码证据。源码目录默认折叠，搜索仍可定位文件、接口与声明。文件视图的左侧为静态反向使用者，右侧为已解析的仓内 import 依赖。桌面上选择节点后会放大到该节点附近，以保留文字可读性；“适配”恢复整张图。

## 内容与准确性

- **人工审阅的关键视图**：17 张图覆盖系统总览、启动、HTTP、会话、实时输出、模型、工具、团队、科研、知识读写、进化、Gym、插件与数据归属。节点包含技术说明和显式实现 owner；节点/关系包含源码路径、锚点和实际行号。owner 不从第一条证据文件猜测。
- **完整源码树索引**：扫描固定 Git commit 的全部跟踪文件，按领域和目录/独立服务入口归属；资源、文档、配置值、提示词正文和二进制仅索引路径。Git 未跟踪内容、安装依赖和活用户数据不纳入。
- **技术导航**：Python AST 符号/import/路由装饰器，TS/JS 启发式声明/import。静态依赖不等于运行调用，局部路由不等于完整 URL，同名测试匹配不等于完整测试覆盖。
- **证据边界**：文件覆盖完整不代表逐函数审阅完整。此图记录源码实现，不宣称产品运行已经验证；历史和实验材料独立标识。
- **保留全部信息的层级浏览**：主流程隐藏部分实现节点，完整实现恢复这些节点；主流程的合并连线只沿原图已有有向路径生成，点击可展开中间步骤。源码目录按领域、源码单元、文件分层和分页，保留全部索引条目。

页面顶部显示来源分支，固定源码版本和生成时间在“更新”中查看。导出的 SVG 是当前图的快照，HTML 保留完整交互。

## 更新同一个 HTML

在按项目规则创建的任务 worktree 中更新；不要在根 `main` 写文档。使用 Python 3.11+ 标准库即可，无产品 import、网络调用或运行数据库访问。

```text
python docs/architecture/build_atlas.py --source <本地main目录> --ref main --previous docs/architecture/index.html --output docs/architecture/index.html
python docs/architecture/validate_atlas.py docs/architecture/index.html
```

构建在开始时解析 `main` 为一个不可变 commit，再通过 Git 对象读取源码，不会混入未提交内容。`--previous` 可与输出同路径，先读旧快照再写新快照；新增、删除和修改文件会进入变更清单。

更新必须包含人工复核：

1. 比对文件变化与 `meta.staleEvidence`。关键流程的任一证据文件内容变化时，页面标记“流程语义待复核”；锚点消失则构建失败，避免沿用失效行号。
2. 审阅变化涉及的调用、状态、存储与授权边界，修改 `curated.py` / `flows.py` 的关系与证据锚点。更新 `runtime_details.py` / `domain_details.py` 的节点说明及 `reading_layout.py` 的阅读分组；新增模块自动进入索引，但新增业务流程需要人工补图。
3. 完成复核后，将 `curated.py` 的 `REVIEWED_COMMIT` 更新为实际审阅的完整 commit，再生成 HTML。不能仅为清除提醒而更新版本。
4. 数据校验同时检查技术说明覆盖、显式 owner、阅读顺序、主流程合并路径，以及生成 HTML 与同目录查看器/叙事源是否一致。另验证离线加载、搜索、下钻、两层切换、节点/边详情和缩放；依项目流程自审、合入本地 `main`。各层验证的真实范围见 `VALIDATION.md`。

`viewer.template.html` 是查看器源模板；`build_atlas.py` 负责索引与嵌入；`curated.py` 和 `flows.py` 保存人工审阅的图意；`runtime_details.py` 和 `domain_details.py` 保存技术说明；`reading_layout.py` 负责职责分区、阅读顺序与主流程层。`index.html` 是唯一需要带走的文件。稳定的模块 ID 使用领域与仓库路径；文件改名后旧定位链接可能失效，可用搜索重新定位。

## 开发边界

本工具只生成文档，不更改产品行为，不要求 Launcher 刷新，不涉及产品版本升级。没有加载外部资源或远程分析脚本；源码正文、实际密钥、完整提示词和用户会话不嵌入 HTML。

可视化基础参考本机 `briefbound-diagram-design` 的离线浅色模板与 SVG 无障碍规范。它的静态自检器仅允许固定动画脚本，不能单独验收本任务明确要求的搜索/下钻交互。数据与 DOM 校验可以验证源码和交互逻辑；整页布局、浏览器兼容性和窄屏表现仍需实际打开 HTML 检查。
