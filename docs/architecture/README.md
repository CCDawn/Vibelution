# Vibelution 开发架构地图

直接打开同目录的 `index.html`。它是离线单文件：无需服务器、安装依赖、联网或启动 Vibelution。首页是整个项目的模块地图，按运行入口、执行核心、业务能力、工程支撑和参考材料组织。点击模块进入职责、边界与源码入口，再进入具体场景的交互流程图。

建议先看首页，再进入“Agent 与会话”模块下的“一条消息的执行过程”。左侧保留全部模块和场景入口，完整源码目录独立折叠。复杂流程先展示主流程，“完整实现”保留调度适配、上下文、授权和存储等原图节点。较长流程在右侧转入下一行，序号和上方导航只帮助阅读，不额外表示执行或调用顺序。

金融主流程分开展示助手初始化与页面行情查询；初始化只分配工具策略，不会直接执行行情工具。Agent 的行情工具授权与执行分支在“完整实现”中查看。

节点详情按输入、处理、输出、边界组织；先进入相关业务流程，再展开源码证据。搜索定位被主流程隐藏的节点时，会切到完整实现并打开对应节点。页面返回恢复来源场景、所选节点和阅读层级，浏览器历史也保留定位信息。文件视图的左侧为静态反向使用者，右侧为已解析的仓内 import 依赖；“适配”恢复整张图。

## 内容与准确性

- **项目结构与模块说明**：15 个领域都有入口，运行模块、工程支撑、实验与历史分别标识；这些领域不是 15 个独立部署服务。总览中的核心关系带源码依据，模块页介绍职责、接口入口、权威边界与可继续阅读的场景。
- **人工审阅的关键视图**：17 张图覆盖运行主线、启动、HTTP、会话、实时输出、模型、工具、团队、科研、知识读写、进化、Gym、插件与数据归属。节点包含技术说明和显式实现 owner；节点/关系包含源码路径、锚点和实际行号。owner 不从第一条证据文件猜测。
- **完整源码树索引**：扫描固定 Git commit 的全部跟踪文件，按领域和目录/独立服务入口归属；资源、文档、配置值、提示词正文和二进制仅索引路径。Git 未跟踪内容、安装依赖和活用户数据不纳入。
- **技术导航**：Python AST 符号/import/路由装饰器，TS/JS 启发式声明/import。静态依赖不等于运行调用，局部路由不等于完整 URL，同名测试匹配不等于完整测试覆盖。
- **证据边界**：文件覆盖完整不代表逐函数审阅完整。此图记录源码实现，不宣称产品运行已经验证；历史和实验材料独立标识。
- **保留全部信息的层级浏览**：主流程隐藏部分实现节点，完整实现恢复这些节点；主流程的合并连线只沿原图已有有向路径生成，点击可展开中间步骤。源码目录按领域、源码单元、文件分层和分页，保留全部索引条目。

页面显著展示来源分支、固定源码提交、提交日期、生成时间与复核状态。它是源码快照，更新 `main` 后不会自动变成最新文档。导出的 SVG 是当前流程图的快照，HTML 保留完整交互。

## 更新同一个 HTML

在按项目规则创建的任务 worktree 中更新；不要在根 `main` 写文档。使用 Python 3.11+ 标准库即可，无产品 import、网络调用或运行数据库访问。

```text
python docs/architecture/build_atlas.py --source <本地main目录> --ref main --previous docs/architecture/index.html --output docs/architecture/index.html
python docs/architecture/validate_atlas.py docs/architecture/index.html
```

构建在开始时解析 `main` 为一个不可变 commit，再通过 Git 对象读取源码，不会混入未提交内容。`--previous` 可与输出同路径，先读旧快照再写新快照；新增、删除和修改文件会进入变更清单。

更新必须包含人工复核：

1. 比对文件变化与 `meta.staleEvidence`。模块说明、总览关系或关键流程的任一证据文件内容变化时，页面标记待复核；锚点消失则构建失败，避免沿用失效行号。
2. 审阅变化涉及的调用、状态、存储与授权边界，修改 `wiki_structure.py` 的模块内容、`curated.py` / `flows.py` 的关系与证据锚点。更新 `runtime_details.py` / `domain_details.py` 的节点说明及 `reading_layout.py` 的阅读分组；新增源码单元自动进入索引，但新增业务模块与流程需要人工补充说明和图。
3. 完成复核后，将 `curated.py` 的 `REVIEWED_COMMIT` 更新为实际审阅的完整 commit，再生成 HTML。不能仅为清除提醒而更新版本。
4. 数据校验同时检查全部领域有模块页、分组无遗漏或重复、场景入口有效、源码证据、技术说明覆盖、显式 owner、阅读顺序、主流程合并路径，以及生成 HTML 与同目录查看器/叙事源是否一致。另验证离线加载、搜索、来源返回、下钻、两层切换、节点/边详情和缩放；依项目流程自审、合入本地 `main`。各层验证的真实范围见 `VALIDATION.md`。

`viewer.template.html` 是查看器源模板；`build_atlas.py` 负责索引与嵌入；`wiki_structure.py` 保存项目分组、模块说明、关键跨模块关系和源码入口；`curated.py` 和 `flows.py` 保存人工审阅的场景图意；`runtime_details.py` 和 `domain_details.py` 保存技术说明；`reading_layout.py` 负责职责分区、阅读顺序与主流程层。`index.html` 是唯一需要带走的文件。源码单元 ID 使用领域与仓库路径；文件改名后旧定位链接可能失效，可用搜索重新定位。

需要锁定已审阅版本时，可在构建命令中使用 `--ref <完整commit> --source-label main`。标签会验证该 commit 属于所标分支，页面仍显示固定版本与日期。文档、资源与历史材料的入口只索引路径；不嵌入其正文，也不冒充代码行号。

阅读层级借鉴 [DeepWiki](https://docs.devin.ai/work-with-devin/deepwiki) 的显式主题页、[C4](https://c4model.com/) 的逐层展开、[arc42](https://docs.arc42.org/section-5/) 的结构与场景分离，以及 [Structurizr](https://docs.structurizr.com/ui/diagrams/navigation) 的下钻导航；保留本项目已有的固定源码证据与离线单文件交付。

## 开发边界

本工具只生成文档，不更改产品行为，不要求 Launcher 刷新，不涉及产品版本升级。没有加载外部资源或远程分析脚本；源码正文、实际密钥、完整提示词和用户会话不嵌入 HTML。

可视化基础参考本机 `briefbound-diagram-design` 的离线浅色模板与 SVG 无障碍规范。它的静态自检器仅允许固定动画脚本，不能单独验收本任务明确要求的搜索/下钻交互。数据与 DOM 校验可以验证源码和交互逻辑；整页布局、浏览器兼容性和窄屏表现仍需实际打开 HTML 检查。
