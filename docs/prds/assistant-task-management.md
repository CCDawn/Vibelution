# 个人助理统一任务管理与团队闭环

状态：用户已授权按本 PRD 开始开发；分期交付，各期按自己的验收范围判断完成。最新范围限定为 Launcher 的助理任务卡片与必要操作，不改平台普通会话。

## 目标

用户向 Launcher 个人助理提出目标，助理选择或启动已授权团队、跟踪原生运行、接收阻塞、推动处置与恢复，并根据实际产物和原目标验收结案。典型对象包括资料搜集团队、开发团队、科研流程及监督进化任务。

助理应持续回答：谁负责、进展如何、为什么阻塞、下一步是什么、是否需要用户决定、原目标是否完成。

本 PRD 记录产品意图；实现与权限权威仍是 [AGENTS.md](../../AGENTS.md)、[开发标准](../standards/development-standard.md)、对应模块 README 和原生 owner。

## 已确认的产品方向

- 仅在 Launcher 个人助理导航中新增“任务”；复用小型弹层显示纵向任务卡片，保留底层助理对话与草稿。
- 普通平台会话的左栏、列表、路由、消息和输入语义均不在本任务范围内；不以助理任务需求修改这些界面。
- 每张卡片默认只显示标题、状态、一句进展与必要操作；编号和结果记录通过详情按需展开，不做多栏管理页或统计面板。
- 任务与消息分开：已读、关闭通知、停止任务和成功结案具有不同含义。
- 默认协助模式；允许用户对具体任务授予有范围、有预算、有期限的托管许可。
- 优先接入现有团队恢复链，助理不能与团队并行发起重复修复。
- 先完成一条资料收集的纵向链路，再扩展开发修复、部署重启和监督进化。
- “与 Agent 消息评级”按“与 Agent 消息平级”解释；没有新增消息质量评分需求。

## 核心对象及权威

| 对象 | 用途 | 权威 |
| --- | --- | --- |
| 助理任务 | 目标、计划、关注信息、授权和关联引用 | 助理任务管理域；不拥有底层执行 |
| 团队运行 | 节点、尝试、执行状态和产物 | 对应团队原生 flow/run owner |
| 问题事件 | 失败、人工门、质量问题、部署等待 | 原生来源事实；接收侧去重并关联 |
| 处置动作 | 一次重试、修复委托、部署或停止请求 | 对应原生动作 owner 与稳定回执 |
| 恢复计划 | 记录待核对的动作、源版本和恢复点 | 管理意图持久化；实际恢复仍通过原生入口 |
| 验收记录 | 用户目标、产物和实际效果的核验结果 | 绑定原任务与已核实来源的验收 owner |

任务卡片是展示投影，不写团队运行状态、Git 集成事实、部署事实或 Session transcript。

## 功能范围

### 团队启动

助理整理目标、输入、目标项目、团队模板、已有角色绑定、交付物、验收条件、预算和允许处置范围。目标与授权明确时直接启动；只询问会改变执行结果的缺失信息。重复启动必须复用原请求关联，不能创建重复运行。

按团队的真实能力展示操作。科研流程暂停只阻止新派发，不能暗示在飞动作已停止；通用流程尚无等价暂停时，不用 stop 冒充 pause。

### 问题接收与诊断

接入失败、无进展、待审批、输入缺失、质量不达标、等待部署及执行结束事件。事件至少关联 project/team/run/node/session/turn/request 的适用身份、发生时间、问题代码、证据引用及原生允许动作。

持久事件优先增量接收；只有查询来源时，使用有界轮询和持久游标补偿。日常只传变化摘要及有界证据，不复制完整日志、Prompt 或第二份 transcript。

重试与恢复仅限已核验可安全执行、原生允许且预算充足的动作。未知副作用保留原请求身份对账。失败升级进入现有修复链；重复事件与扫描不新建第二个修复子任务。

### 开发修复

修复子任务关联原问题、复现证据、允许修改文件、验收条件、授权期限、预算和原任务身份。执行沿用隔离候选、开发、独立审查、质量门和唯一集成 owner。

独立展示以下结果：代码已合入、已部署、原问题复验通过、原任务目标达成。前一阶段的成功不能替代后一阶段。

### 部署与恢复

固定候选版本及目标实例；保存恢复计划；按授权停止受影响任务并部署；经 Launcher 正规链路重启；重新发现实例、核对实际版本、检查健康与原问题的业务效果；随后通过原生 owner 继续原任务。

第一版优先控制项目运行实例。Launcher 自身升级重启单独设计宿主交接，不隐含在项目恢复内。自动托管影响其他活跃工作时等待安全时机；用户明确批准立即重启时，先保存并正规停止，再执行。回滚仅限具备已核实兼容条件的已授权路径。

### 监督进化

统一查看目标、数据集和评测版本、轮次、候选、成本、剩余预算、暂停/继续/停止、授权撤销和晋级建议。沿用现有进化控制及唯一候选晋级 owner。故障进入回归案例，同时保留独立评测案例；不能凭候选自评直接晋级。

## 界面契约

“任务”仅是 Launcher 自己的导航入口，打开现有 VDialog 形式的小型卡片列表。首版不增加统计、搜索和筛选栏；支持读取实际已登记的助理派遣和已关联团队运行，明确其覆盖范围。

卡片默认显示标题、状态和一句进展，最多突出一个需要用户决定的操作。详情按需展开结果和来源引用。核对任务通过原助理对话提出受限的只读请求；审批返回已有原生审批面，不从卡片自动同意。打开、关闭任务不卸载原助理对话，不清空输入草稿。

来源离线或过期时显示“状态待核实”和最后已知事实。合法空、来源不可用、分页未读完与有界历史必须区分；不能将部分派遣记录解释成全平台任务清单。

团队卡片从助理持久化的 `team_run` / `flow_start` 关联读取原生运行状态，不扩大为全平台团队目录。每页最多 16 条，沿用“显示更多”和“刷新”，不增加新的管理页面。启动请求受理与团队运行状态分开；团队结束先显示“待验收”，`waiting` 显示“待输入”并回到对话核对，不能当作工具授权。卡片不直接重试、停止或重启团队。

团队来源使用身份绑定的只读 Host/IPC；状态能力 `teamRunsVersion:1` 声明支持。旧宿主仍可读取派遣卡片。团队查询失败保留未知记录，派遣来源继续可用；分页关联或项目绑定变化时从首页重新核对，不混合不同快照。返回对话只带固定只读请求与来源标识，不把团队名称、结果正文转成指令。

新增界面在隔离预览批准后进入正式 owning surface，遵循现有 VUI 和页面 recipe。

## 完成和停止

成功结案同时要求：原生业务成功、约定产物可访问、目标验收通过、关联子任务收口或明确移交、无影响结论的未知执行结果。原生 succeeded/completed、派遣送达、模型结果摘要、Git 合入和服务健康均不能单独证明目标完成。

停止后保留部分成果与原因，不标为成功。撤销后阻止新动作，在飞动作继续核实到安全结束。

## 授权和可靠性

- 只读与动作分离；已有授权不隐式扩张到项目、分支实例、文件或工具。
- 审批绑定对象、版本、影响与恢复方案；来源变化后重新核验。
- 事件与操作使用稳定身份；未知结果查询原回执，不换 ID 重放。
- 同一处置单一执行 owner；父子任务共享总预算与期限，重启不重置累计消耗。
- 团队消息、资料正文、错误与日志为不可信数据，不作为授权或执行指令。
- 所有产品后台进程遵循 Windows 无可见控制台红线。

## 分期和依赖

| 阶段 | 交付 | 完成证据 |
| --- | --- | --- |
| 一：任务可见与基础推进 | 任务入口、来源关联、团队发现启动、问题聚合、安全推进和结果验收 | 助理启动资料收集试点，处理真实临时故障并展示可核验产物 |
| 二：修复与部署恢复 | 接入既有修复链、受限实例控制、部署授权、版本及效果复验、原任务恢复 | 真实故障经修复部署后，原失败节点恢复并完成目标 |
| 三：进化托管 | 监督进化管理、有限多轮计划、预算、对照及晋级、回归沉淀 | 授权期限内完成一轮对照，给出有证据的晋级或拒绝结果 |

一期实施顺序：

1. 固定来源边界及安全状态投影；先覆盖成功不可冒充验收、失联不可冒充空、稳定身份及去重。
2. 制作复用 VUI 的隔离交互预览；预审通过后接入正式 Launcher 左栏。
3. 接入已存在的派遣只读入口；团队与 runtime 来源通过其 owning Host/IPC 提供有界、含覆盖信息的只读投影，renderer 不读取项目凭证或直连任意项目接口。
4. 按能力关联原生查询和审批；试点流程验证启动、故障、安全推进和结果验收。
5. 完成分支验证、自审及本地合入；运行实例刷新按独立授权执行，未刷新不宣称正式页面已生效。

当前并行开发的监护、管理动作和 Research 命令保留在原 owner。本任务优先承担任务展示与来源适配，不复制监护循环或修改其正在开发的执行链。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 重复启动 | 同一请求关联一个原生运行 |
| 重复故障推送 | 更新原问题，不生成重复任务或修复 |
| 既有恢复进行中 | 跟踪原 owner，不另起恢复 |
| 非幂等操作超时 | 原身份对账，保持未知，不自动重放 |
| 窗口关闭或宿主重启 | 关联与恢复计划保留，重连核对事实 |
| 修复合入未部署 | 等待部署，不宣称问题解决 |
| 重启后加载旧版本 | 效果验收不通过，不自动续跑 |
| 撤销托管 | 无新增动作，在飞动作据实跟踪 |
| 原任务执行结束但目标未达成 | 任务不成功结案 |
| 来源不可用或未完成分页 | 显示覆盖缺口，不报告无任务 |
| 不同项目使用同名运行 ID | 保留独立身份，不混合状态与权限 |

指标先采基线：闭环完成率、恢复耗时、人工决定次数、重复处置率、错误结案率、中断恢复成功率、单位恢复成本。重复副作用、越权与虚假完成在验收场景中要求为零。
