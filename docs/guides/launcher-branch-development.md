# 分支工作台开发与验收

内部和外部 Agent 使用相同流程。隔离单位是一个固定路径的 Git worktree；同一目录内切换 branch 不会创建新的运行实例。

## 开发顺序

1. 按 [协作规范](../agents/worktree-collaboration.md) 从当前本地 `main` 创建任务 worktree，并检查任务范围与 claim。
2. 先运行与修改有关的测试。需要真实后端或界面验收时，用 Launcher 启动**任务目录**，或在 Launcher 中启动对应分支行：

   ```powershell
   & "$env:LOCALAPPDATA\Vibelution\Launcher\VibelutionLauncher.exe" --project "<task-worktree>" start
   ```

3. 用 `scripts/desktop_debug.py --project "<integration-root>"` 发现当前 Launcher，再从对应实例记录取得端口和工作台 URL。不要默认使用 `8000`，不要用 `main` 工作台代替任务实例。
4. 对该实例请求 `/api/health`，核对：`routesReady == true`、`workspaceRoot` 等于任务目录、`serving.backend.head` 对应任务版本，以及 `serving.frontend.builtFromCommit` 和构建产物来自任务目录。未提交开发态同时记录 `dirty`、`dirtyTreeDigest`；提交或修改后重新判断该证据是否仍对应被验收内容。
5. 在这个 URL / 窗口完成任务行为验证。记录实例目录、端口、真实 PID、版本和实际操作结果；CLI 返回零或 registry 接收命令，只代表该层结果，不能替代健康与行为验证。
6. 完成自审及最终检查后，使用 `scripts/task_closeout.py` 合入本地 `main`。合入前先停止本任务试验进程，合入后清理本任务资源。不得停止别人的实例来帮助自身合入。

如果 CLI 返回成功而目标实例仍未运行，记录请求及目标状态；可以在 Launcher 对应分支行重现并定位问题。禁止直接运行另一套后台监督进程，或把其他实例的 HTTP 200 当作成功。若命令转发没有可靠结算，不应让无人值守 Agent 继续后续验收或合入步骤。

## 实验团队

长期实验使用固定版本、固定路径、单独保留的 worktree。普通开发在其他任务实例完成，合入 `main` 不会自动升级实验实例。实验目录不属于普通任务的清理范围。

进程和业务数据按实例分开，但当前 operator 配置与 Python 工具链仍共享。只读复用相同依赖可行；不得为了一个开发分支修改共享环境或共享配置。确需不同配置/依赖时，先明确隔离方案。GPU 是整机资源，当前算子试验使用 device-0 全局租约，不能把多进程理解成独立 GPU。

Launcher 桌面壳是所有实例的共同控制进程。刷新/退出整个壳可能停止全部实例；这与重启一个分支工作台不同。涉及桌面壳升级时，必须单独安排实验停机边界。

## 2026-09-15 试点证据与边界

在相同的本地源版本上创建 A、B、实验三个独立 worktree，经 Launcher 控制页的正式 IPC 启动，分别得到 `8001`、`8002`、`8003` 后端。健康响应确认各自的目录与前后端版本。重启 A 后其 PID 改变；停止、再次启动 A 时，B 与实验实例在连续健康采样中 PID 不变且路由保持就绪。

实验实例本轮只运行工作台与初始化服务，没有执行付费模型、真实研究任务或 GPU 负载，因此上述证据证明的是实例生命周期隔离，不是长期实验或资源性能隔离。期间主实例收到另一条 stop 命令，主实例连续性不纳入本次通过结论。

原生 CLI 首次启动请求未产生目标实例，却因默认端口上的主实例健康而报告成功。已为启动复用检查增加请求目录与路由就绪校验，并改用目标实例端口；相同端口指向别的 worktree 时回归测试和真实 HTTP 探测均拒绝成功。原生命令为何未到达目标实例的转发问题仍需独立定位，不能把控制页 IPC 试点通过写成 CLI 端到端通过。

本契约要求 Agent 留下分支运行证据；当前自动合入质量门尚未强制校验该证据，不能宣称已完成无人值守的全链路约束。
