## 结论

当前界面已有一组共享的 VUI 表面 token，但产品层并未统一以“语义角色”消费它们。相同的视觉层级会在不同路由以不同 alpha 混合值表达，因此大屏背景或背景图存在时，卡片的透底感不稳定。这是“卡片透明度看起来不统一”的直接工程原因之一；是否保留某个具体透明度，须在 Reference Lab 评审后再决定。

## 现有契约与风险边界

- 主题源头在 `web/src/design/tokens.css`；默认根主题与 `[data-theme="light"]` 已提供相同变量名下的不同值。
- `web/src/components/vui/product/VSurface.tsx` 已存在 `panel / rail / glass / toolbar / row` 等表面语义，但不少路由仍直接叠加 alpha，绕开统一层。
- Agent 管理页是高密度、三栏、存在背景图的典型场景；它不应先以“再加一个 alpha”修复，而应先确定背景与容器是否分层、哪些层必须不透明。
- 本次 Lab 只新增未接入路由的开发预览文件，绝不改动 `tokens.css`、VUI renderer 或现有 Agent 管理页。

## Reference Lab 验收要点

1. 在浅色、深色、普通背景、情境背景四种组合下，卡片正文的可读性一致。
2. 页面背景、区域底、卡片、内嵌区域、控件、浮层可被清晰区分，且每种角色只有一个预览映射。
3. 主要按钮高度、边框、圆角和强调层级有明确的有限集合；禁用/焦点/危险状态可辨认。
4. Reference Lab 为隔离预览。只有用户明确批准后，才可以将确认过的映射写入正式 token 和 VUI 组件。

## 后续决策门

待用户在 `vui-reference-lab.html` 完成视觉评审后，才进入设计令牌契约任务。建议在批准时确认：

- 普通内容卡是否一律不透明；
- `glass` 是否只保留给浮层与临时操作层；
- 常规与紧凑控件高度；
- Agent 管理、对话、团队、Kernel、记忆库的试点顺序。
