# 快速配置紧凑单页改版设计

**Status:** approved-direction / pending-spec-review
**Date:** 2026-07-13
**Owner:** web-workbench-surface
**Target:** `/config` → 模型库 → 快速配置
**Version impact:** patch

## 1. 设计结论

采用用户选择的 **A 方案：紧凑单页渐进流程**。

本设计修订并取代 `2026-07-12-config-quick-setup-design.md` 第 6 节的“永久左右双栏、稳定尺寸结果区”布局约束。旧设计的数据、配置事实源、凭据安全和确认后才保存等约束继续有效。

快速配置首屏只保留一条连续操作路径：

1. 选择服务商；
2. 按模板要求输入 API Key；
3. 点击“检测连接”；
4. 检测成功后在同一区域下方确认模型并“保存并完成”。

检测前不渲染占据半屏的结果面板。结果、错误和保存确认只在对应状态出现。

## 2. 用户目标与成功信号

目标用户是不熟悉 Provider、协议和模型目录细节，但希望尽快完成可用模型连接的本地用户。

成功信号：

- 首屏一眼能看出需要填写什么以及唯一的下一步；
- 标准 Provider 从输入到预览只需一次点击，从预览到正式保存只需一次确认；
- 空闲状态没有大面积空结果框、重复标题或说明性卡片；
- 检测、失败、确认和保存反馈均靠近触发操作，不依赖全局提示；
- 1920 像素桌面宽度下内容保持紧凑，不因可用空间变宽而拉伸控件。

## 3. 范围

### 3.1 本轮包含

- 重排 `ConfigQuickSetupPanel` 的信息层级和桌面布局；
- 将服务商、API Key 和主操作收敛为一个有界的配置工作区；
- 检测前隐藏结果容器，检测后在输入区下方渐进展示状态或预览；
- 统一主按钮的 idle、disabled、busy、retry 和 success 反馈；
- 保留高级参数折叠区，但降低其首屏视觉优先级；
- 更新组件和布局契约测试，并进行桌面浏览器视觉验证。

### 3.2 明确不做

- 不做手机端或触屏适配；
- 不修改后端 API、Provider draft、模型推荐算法或 operator config 写入协议；
- 不增加新的 Provider 模板、凭据存储或模型事实源；
- 不重做“管理已有连接”和“高级设置”；
- 不自动保存，也不跳过最终确认；
- 不引入新的前端依赖或页面级 HeroUI 直引。

## 4. 页面布局

### 4.1 空闲输入态

快速配置内容使用左对齐、有最大宽度的桌面工作区，避免在超宽屏上无限拉伸。工作区包含：

- 紧凑标题：“连接一个模型服务”；
- 一行主输入带：服务商选择、条件显示的 API Key、主按钮“检测连接”；
- 一行短提示，只保留凭据不会回显和检测不会正式写入两项必要信息；
- 默认收起的“高级参数”入口。

服务商选择和 API Key 可占据剩余宽度，主按钮贴合内容并保持稳定高度。不得为短标签创建整行大按钮或永久空白卡片。

### 4.2 检测与错误态

- 点击后主按钮原位变为“检测中…”，宽度保持稳定并禁用重复提交；
- 检测进度在输入带下方以紧凑状态行出现，不创建第二个等高面板；
- 错误在输入带下方就地显示，保留服务商和本次输入，主按钮变为“重新检测”；
- 认证错误关联 API Key；端点或协议错误提供展开高级参数的入口；
- 错误、降级和部分完成不得显示为成功。

### 4.3 预览与保存态

检测成功后，在输入带下方展开全宽预览区，包含：

- Provider、端点、协议、发现模型数量的紧凑摘要；
- 默认模型选择器和推荐理由；
- 次操作“重新检测”；
- 主操作“保存并完成”。

保存中主按钮原位显示“保存中…”。保存成功后展示紧凑成功摘要和当前 Provider/模型；不恢复空闲态的大面积占位。

## 5. 状态与按钮契约

| 阶段 | 主操作 | 可用条件 | 邻近反馈 |
| --- | --- | --- | --- |
| `input` | 检测连接 | 已选模板，且需要认证时已输入 API Key | 无永久结果区 |
| `checking` | 检测中… | 禁用 | 紧凑进度状态 |
| `error` | 重新检测 | 输入满足条件 | 原地错误与恢复指引 |
| `review` | 保存并完成 | 已选择默认模型 | 配置摘要与推荐理由 |
| `saving` | 保存中… | 禁用 | 保留预览，避免布局跳动 |
| `success` | 已完成 | 禁用或不显示 | 已保存 Provider/模型摘要 |

按钮的 busy、disabled、error 和 success 状态不得改变所在行高度。状态必须使用文字，不只依赖颜色。

## 6. 组件与数据边界

- `ConfigQuickSetupPanel` 只重排现有 props 和会话状态的呈现，不直接调用 API；
- `ConfigRoute` 继续拥有检测、保存、workspace 刷新和错误状态；
- `configProviderLogic.ts` 的模板映射和模型推荐规则保持不变；
- VUI 继续提供输入、选择、按钮、状态和折叠 primitives；
- 正式配置仍以 `C:\Users\17533\Documents\Vibelution\config\config.toml` 为唯一 operator source of truth。

本轮不增加并行事实源、缓存或配置写入路径。

## 7. 可访问性与桌面约束

- 保留服务商和 API Key 的可见标签；
- 焦点顺序为服务商、API Key、高级参数、检测、模型选择、保存；
- loading/error/success 使用图标与文字双重表达；
- 主输入带在 1280、1600、1920 像素桌面宽度下不得溢出或覆盖；
- 不定义移动端重排契约；窄于目标桌面宽度时允许页面正常滚动，但固定操作不能遮挡内容；
- 浅色、深色主题下均保持边界、焦点和错误对比度。

## 9. 日志、模式与发布判断

- Logging：不新增日志分支。本轮不改变检测和保存行为，复用现有配置 mutation 的有界日志；凭据仍不得进入日志。
- Developer/formal mode：parity preserved，共享同一 UI 和配置契约。
- Runtime refresh：实现后、用户测试前 required。
- Project memory：合入本地 `main` 后同步 `web-workbench-surface` lane。
- Version impact：patch；任务 Agent 只报告，不直接修改版本文件。

## 10. 验收标准

- 用户进入快速配置后，首屏不再出现占半屏的“等待检测”空面板；
- 服务商、API Key 和检测操作形成一个连续、紧凑、清晰的操作区；
- 检测结果仅在检测开始后出现，成功后原位进入模型确认；
- 按钮反馈与阶段一致，禁用、忙碌、错误和保存状态无歧义；
- 输入失败后无需重新选择 Provider 或重新输入非敏感字段；
- 不改变配置事实源、后端 API、凭据安全和最终确认语义；
- 三个桌面视口和双主题通过真实浏览器验证。
