# 桌面设置控制台整体重构设计

**Status:** approved-direction / pending-spec-review
**Date:** 2026-07-13
**Owner:** web-workbench-surface
**Target:** `/config` 全部设置分区
**Version impact:** patch

## 1. 设计结论

采用用户确认的 **A 方案：桌面设置控制台整体重构**。

本轮不再以单个按钮、卡片或 Provider 面板为修补单位，而是统一重构 `/config` 的信息架构、页面高度、控件尺寸和反馈语言。核心结构为：

1. 左侧只负责一级设置分区导航；
2. 顶部只保留一套全局配置状态与保存操作；
3. 主内容区一次只显示一个设置子页面；
4. 普通配置采用一致的桌面表单布局；
5. 模型连接采用填满可用空间的工作区布局；
6. 原始配置和低频诊断退出默认首屏，按需进入。

正式配置继续以 `C:\Users\17533\Documents\Vibelution\config\config.toml` 为唯一 operator source of truth。本轮不改变配置 API、字段语义、Provider 检测流程或保存协议。

## 2. 已确认的问题

### 2.1 信息架构

- 左侧栏同时承担项目说明、同步状态、分区导航和开发者信息，导航入口被大量次要内容挤压；
- 顶部工作台和“保存与生效”子区重复展示配置路径、同步状态和相同操作；
- 总览默认展开整份原始配置编辑器，普通用户一进入设置就面对高认知负担内容；
- 一个一级分区内多个子区纵向堆叠，用户需要滚动寻找当前目标。

### 2.2 布局与尺寸

- 页面容器以 `align-content: start` 为主，不同子区按内容高度收缩，造成模型管理页上方拥挤、下方大面积空白；
- Provider 列表只有最大高度，没有填满工作区；详情面板也随少量内容收缩；
- 多数操作按钮和字段控制在 27–30px 高度，Provider 行和左侧导航点击区域偏小；
- 各分区的标题、卡片、表单、工具栏和操作区采用不同密度，视觉节奏不一致。

### 2.3 操作反馈

- 同一动作在多个位置重复出现，用户难以判断哪一个是主操作；
- disabled、busy、success 和 error 虽然有局部实现，但位置、尺寸和反馈文案缺少统一规则；
- 状态信息与触发操作相距过远时，用户需要在页面中寻找结果。

## 3. 用户目标与成功信号

目标用户希望在不了解内部配置结构的情况下，快速找到设置并完成修改。

成功信号：

- 进入 `/config` 后 3 秒内能识别当前所在分区、配置是否已保存以及唯一主操作；
- 任一常用配置在一级分区和一个子页面选择后即可开始编辑；
- 普通设置不需要接触原始 JSON/TOML 结构；
- 页面只存在一个主要纵向滚动容器，不出现内容区与表格互相争抢滚动；
- 1280、1600、1920 像素桌面宽度下按钮、标签、字段和状态对齐一致；
- Provider 列表、详情和模型表格使用可用高度，不再出现“顶部一小块内容、底部整屏空白”。

## 4. 范围

### 4.1 本轮包含

- 重构 `/config` 一级导航、全局页头和内容工作区；
- 为每个一级分区增加清晰的本地子页面导航，一次只展示一个子页面；
- 去除总览、页头和子区之间的重复状态与重复操作；
- 统一普通表单、选择器、按钮、卡片、状态条和危险操作的尺寸与间距；
- 重构快速配置、已有连接管理和高级模型设置在主工作区中的高度与宽度使用；
- 重构 Provider 列表行、连接详情、模型表格和底部危险操作区；
- 统一保存、检测、重新读取、错误和成功反馈；
- 更新布局契约、组件测试并完成桌面浏览器视觉验证。

### 4.2 明确不做

- 不做手机端、触屏端或窄屏响应式适配；
- 不修改后端配置 API、Provider draft、模型发现、路由、推荐或保存语义；
- 不改变外部 operator config 路径和所有权；
- 不新增 Provider 模板、配置字段或凭据存储能力；
- 不把 Launcher 启动设置迁入 `/config`；
- 不引入新的前端依赖，不绕过 VUI/HeroUI 组件边界；
- 不顺带重构与设置无关的应用顶部栏和其他路由。

## 5. 整体页面结构

### 5.1 一级设置导航

左侧设置栏只保留：

- 页面身份：设置；
- 一条紧凑同步状态；
- 六个一级分区：总览与保存、界面与高级配置、用户与形象、模型库、运行时与上下文、工具与诊断。

开发者模式详情、默认入口、运行档位等信息移入“工具与诊断”对应子页面，不继续占用导航区。分区数量徽标仅在能够表达未完成项、问题或有效子页面数量时显示，不作为装饰性常驻元素。

一级导航行最小高度为 44px，整行可点击；选中态同时使用背景、边框和文字层级表达，不只依赖细描边。

### 5.2 全局页头

主内容顶部只保留一套全局控制：

- 当前一级分区标题和一句短说明；
- 当前配置状态：已同步、未保存、保存中、保存失败；
- 次操作“重新读取”；
- 主操作“保存更改”。

配置路径不再占据独立大卡片；放入状态详情或可复制的次级信息中。系统环境变量入口移入“工具与诊断”，避免与日常保存并列。

页头在主内容滚动时保持可见。按钮 busy 状态原位切换，不改变宽度或造成工具栏跳动。

### 5.3 本地子页面导航

每个一级分区在页头下方提供一行本地子页面导航。一次只渲染一个子页面，不再把同组所有面板纵向堆叠。

建议映射：

- 总览与保存：状态总览、变更与保存；
- 界面与高级配置：工作台行为、界面显示；
- 用户与形象：用户资料、终端形象、陪伴体；
- 模型库：模型连接；其内部保留快速配置、管理已有连接、高级设置三种模式；
- 运行时与上下文：运行时、上下文压缩；
- 工具与诊断：工具与权限、日志与调试、Git 提交、健康诊断、原始配置。

一个本地子页面可以组合少量强相关的底层配置分区，例如“Git 提交”同时承载 `git-commit-model` 和 `git-commit-prompt`。这两个既有配置当前没有归属到任何一级分区，本轮必须恢复其可达入口；组合页面仍遵守“一次只显示一个设置子页面”。

切换子页面不得丢失当前结构化草稿。存在未保存修改时切换分区不弹阻断对话框；全局页头持续显示“未保存”。

### 5.4 主内容工作区

设置路由在应用可用区域内形成固定高度工作区：

- 根布局和主内容使用 `min-height: 0`；
- 页头和本地导航按内容占高；
- 当前子页面使用 `minmax(0, 1fr)` 填满剩余高度；
- 默认只有主内容区域负责纵向滚动；
- 需要大量数据的模型表格可以在自身区域滚动，但不能与外层形成两个同方向的永久滚动条。

普通设置内容采用舒适宽度，不在超宽屏无限拉伸；模型管理、原始配置和诊断表格允许使用全部可用宽度。

## 6. 普通设置表单规范

普通结构化配置统一使用双列桌面表单：左侧标签和必要说明，右侧输入控件。短布尔项和单选项可在一行内完成，不创建大面积空卡片。

尺寸约束：

- 一级导航行：最小 44px；
- 普通按钮、输入框、选择器：40–44px；
- 紧凑次操作仍不得低于 36px；
- 表单行垂直间距：12–16px；
- 区块间距：20–24px；
- 正文不得以 `xs` 作为默认字号，`xs` 只用于眉题、辅助元数据和非关键标记。

字段说明只在帮助用户做决定时出现。内部字段名、结构化路径和实现细节不作为普通视图的主要标签。

## 7. 总览与原始配置

### 7.1 状态总览

总览只展示：

- 当前配置源与同步状态；
- 未保存修改或阻塞问题摘要；
- 最近一次检查结果；
- 跳转到最常用设置的快捷入口。

不重复全局页头中的保存按钮，不直接展开原始配置编辑器。

### 7.2 原始配置

整份原始配置编辑器移入“工具与诊断 → 原始配置”。进入该子页面后才加载和展示编辑器，并明确标注为高级操作。

原始配置检查、还原和诊断反馈固定在编辑器附近。结构化配置与编辑文本的一致性语义保持现状；不新增第二份配置状态。

## 8. 模型连接工作区

### 8.1 模式切换

“快速配置 / 管理已有连接 / 高级设置”作为模型连接内部的稳定模式切换，位于同一工作区顶部。切换模式时标题和说明不重复创建新的页面头。

### 8.2 快速配置

沿用已确认的渐进式流程，但取消导致内容孤立在大画布左上角的过窄工作区。输入、检测反馈和结果区域在桌面主栏内保持明确宽度；检测前不渲染永久空结果面板。

### 8.3 管理已有连接

管理页采用全高两栏：

- Provider 侧栏宽度使用有界值，目标约 `clamp(22rem, 28%, 28rem)`；
- Provider 行最小高度 58px，整行可点击，名称、标识和状态形成稳定三层信息；
- Provider 列表填满可用高度并独立滚动；
- 详情区使用剩余宽度和高度，连接摘要、模型、协议能力和诊断通过标签页切换；
- 连接摘要使用明确的事实卡片网格，但不得随少量内容收缩为页面顶部窄条；
- 模型表格填满详情区剩余高度，表头固定，操作列保持对齐；
- 删除 Provider 等危险操作固定在详情底部危险区，不夹在普通事实卡片之间。

没有选中 Provider、加载中、无模型和错误状态都必须填充详情工作区并提供明确下一步，不留下无说明空白。

### 8.4 高级设置

高级模型配置仍使用结构化分区编辑，但只显示当前选中的配置分区。原始字段和诊断信息不得与普通 Provider 管理同时堆叠。

## 9. 状态与按钮反馈契约

| 状态 | 全局页头 | 触发按钮 | 邻近反馈 |
| --- | --- | --- | --- |
| `synced` | 已同步 | 保存更改禁用 | 无重复成功卡片 |
| `dirty` | 有未保存修改 | 保存更改启用 | 当前字段保留修改提示 |
| `saving` | 保存中 | 原位显示保存中并禁用 | 保持页面尺寸稳定 |
| `saved` | 已保存 | 短暂确认后回到禁用 | 就近文字确认，不新增大面板 |
| `error` | 保存失败 | 允许重试 | 错误靠近操作并可定位到分区 |
| `checking` | 状态不冒充已保存 | 检测按钮原位忙碌 | 结果在检测区域内出现 |

通用规则：

- 主按钮每个页面只允许一个；
- disabled、busy、success、warning 和 error 必须同时使用文字，不只依赖颜色或图标；
- 操作反馈优先显示在触发区域附近，全局状态只总结配置整体状态；
- busy 和反馈变化不得改变按钮行高、工具栏宽度或表格列宽；
- 危险操作使用独立危险区和二次确认，不与主保存操作并排竞争。

## 10. 组件与数据边界

- `ConfigRoute` 继续拥有配置查询、结构化草稿、原始编辑文本、检查、保存和 Provider workspace 刷新；
- 本轮可以从 `ConfigRoute` 提取纯展示或局部导航组件，但不得创建新的配置事实源；
- `ConfigProviderRegistryPanel` 继续拥有 Provider 局部选择、模型搜索筛选和标签页展示；
- `ConfigQuickSetupPanel` 继续通过 props 接收检测、保存和状态，不直接新增 API 调用；
- `configProviderLogic.ts`、API DTO 和后端配置接口默认不变；若实现中发现必须修改，停止并重新评审范围；
- 样式继续 Tailwind-first，并通过 VUI 组合；route 文件不得新增页面级 HeroUI 直引。

## 11. 可访问性与桌面约束

- 所有输入保留可见标签，不能只依赖 placeholder；
- 一级导航、本地导航和模式切换具有明确的选中语义；
- 键盘焦点顺序与视觉顺序一致，焦点样式不能被容器裁剪；
- 长 Provider、模型和配置路径使用截断加完整可访问名称或 title，不挤压操作列；
- 浅色和深色主题均验证边界、对比度、焦点、错误和禁用态；
- 目标视口为 1280×720、1600×900、1920×1080；不定义手机端重排契约；
- 小于目标桌面宽度时允许出现页面级最小宽度和滚动，但固定操作不得遮挡内容。

## 13. 日志、模式与发布判断

- Logging：不新增凭据或配置全文日志；复用现有配置查询、检查、保存和 Provider mutation 的有界日志。若交互状态新增异常分支，只记录状态名和配置分区，不记录值。
- Developer/formal mode：parity preserved，共享同一设置结构和保存契约。
- Runtime refresh：实现后、真实浏览器验证前 required。
- Project memory：合入本地 `main` 后同步 `web-workbench-surface` lane。
- Version impact：patch；重构改变前端信息架构和交互布局，但不改变外部配置或 API 契约。任务 Agent 不直接修改版本文件。
