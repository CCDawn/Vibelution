# Launcher 助理平台管理闭环修复

用户已授权按平台能力评估开始修复。实现位于 `codex/assistant-platform-management`；本文件记录本轮执行边界，不替代现行规范或运行时事实。

## 结果与验收

- 派遣和建议发现连续翻页不会因 4096 边界静默终止，模型实际收到的每页仍完整。
- 管理请求可在重启和跨轮后发现原 project/action/requestId；旧无元数据关联明确报告覆盖缺口，不猜测、不换请求重放。
- 新的独立授权运行视图汇合已有任务、Session Turn、团队与进化 owner 的元数据，逐源报告覆盖与故障，不能把缺失来源或未知当作空闲。
- 助理可经既有原生审批调用精确对象/版本绑定的任务停止、团队运行控制和安全续接；受理、停止请求和实际终态分别核验。
- 自己发起的团队工作在完成、失败或停止后进入既有 patrol/native follow-up，重启不重复投递，不将外层受理当作业务完成。
- 补齐既有团队、目标 Agent 工具权限及知识 ACL 的结构化管理适配，复用原 owner 与权限校验，不开放任意 HTTP/命令或直接改状态文件。
- 模型/厂商删除停用只在全项目及助理引用可以可靠核验时接通；不能通过移除引用校验交付。

## 所有权和依赖

1. 发现与恢复：`discovery_actions.py`、`management.py` 和独立发现模块，先完成分页回归与请求引用持久化。
2. 原生运行适配：先只读定位已有 owner，随后主 Agent 负责 DTO、SDK、route、service、tool/approval 集成；普通 Session 核心不作补丁。
3. 团队后续：`patrol.py`、`host.py` 与独立 team 适配模块；消费第 1 项管理请求引用，与第 2 项控制操作串行集成。
4. 授权与已有对象管理：在运行闭环可用后接入团队、toolPolicy/ACL 与配置引用检查，保持共享 schema/SDK 单一写入者。

独立实现并行，共享契约由主 Agent 串行集成。测试、说明和验证属于各自实现，不另建任务。

## 契约与保护

采用新增可选 scope、闭合 DTO 和新增动作；既有 SDK bootstrap grant、普通 Agent/Session 行为、full_access 自动批准语义不变。写操作继续使用原生管理审批、CAS 与稳定请求键。未知结果只读取原回执，不能以不存在或响应超时作为未执行证明。项目运行记录、Journal、团队运行和配置 owner 继续是唯一事实源；发现目录和 patrol 只保存引用及投递幂等记录，不复制正文。

新增控制必须先有目标预览/元数据与精确版本；不把本轮开发授权解释为取消现有真实任务、删除数据或替所有 Agent 扩权的指令。活数据验收以只读检查和隔离临时对象为主。

## 验证与交付

先用窄回归验证真实缺陷及新增状态/权限契约，再做独立审查、完整 selector、自审和本地 ff-only 合入。前端改动仅复用现有 VUI 审批展示，运行 TypeScript 及对应 VUI 契约。运行更新只走官方 Launcher，后台 CDP/preload 验收，禁止抢焦点。实际助理必须完成“发现—查询—受控操作—原回执—当前状态”的隔离业务场景后才宣称管理闭环已修复。

版本影响为新增可选管理能力；本轮不 push、PR 或远端发布。失败时保留原数据/回执，新动作默认不可用，不用宽松 fallback 绕过绑定或来源检查。

## 实现与收口进度

已接通独立运行管理、既有团队/Flow、工具权限与ACL原生适配，并补齐请求引用恢复和团队/Flow终态跟进。独立审查发现的注册表内容CAS、raw/effective策略比较、读取副作用、未知回执重放、Flow写后失应答分类和团队角色权限展示均已修复并有对应回归。查询保持existing-only，缺失来源和覆盖不足显式返回；普通Session核心未修改。下一步以最终selector、自审及本地合入为代码验收，再按官方Launcher刷新和后台真实助理场景确认交付。跨项目模型/厂商删除仍受原引用权威缺失限制，本轮不以放宽引用校验代替修复。
