## 已发现问题

### P0：候选确认后无法从前端完成假说选择

**现象**：确认候选生成纪要后，前端自动导航到 `node=hf_selection`，但右侧详情被正式运行的“假说设计”状态占用，只显示“当前任务在其他步骤，请前往当前步骤”。点击“假说选择”仍没有候选复选框或“记录选择”按钮。

**结构证据**：假说先行进度为 `1/2`，`hf_generation` 已完成，`hf_selection` 仍为未开始；与此同时正式运行已经进入 `hypothesis_design` 并阻塞。前端 `HypothesisFirstNodeInspector` 在 `formalRuntime` 为真时优先返回正式运行操作体，使已经选中的 `hf_selection` 分支无法渲染 `HypothesisSelectionList`。

**影响**：操作者不能仅通过流程画布完成候选筛选和开启评审，因此“前端独立产生高质量假说”的第一阶段闭环当前不成立。

**状态**：未解决。验收中不使用后台 API 绕过该入口。

### P0：正式运行早于假说先行完成，形成前置条件阻塞与操作面争用

**现象**：假说先行仍为 `1/2` 时，正式节点已从问题理解推进到假说设计，并因 `hypothesis_round_unconverged` 阻塞。

**权威证据**：Ledger 中 `problem_understanding` 为 `succeeded`，`hypothesis_design` 为 `blocked`；主运行 active node 为 `hypothesis_design`。此时前端的候选选择仍未开始。

**影响**：运行状态把“等待操作者选择”表达为正式节点失败/可恢复，同时正式运行操作面覆盖人工选择操作面，增加恢复歧义和无效重试风险。

**状态**：未解决。不得点击“重试假设设计”，因为缺失的假说选择和知识包尚未补齐，重试不会消除根因。

### P1：候选清单没有在生成阶段执行范围一致性门禁

候选 3 使用“无细胞转录-翻译（TX-TL）系统”，与同一运行冻结的问题理解假设“工程化生命材料必须含有保持活性并参与材料构建或功能的生物组分；完全无细胞材料只作为背景对照”直接冲突，但仍进入正式候选清单。

候选 1 直接给出 `0.2 → 0.05 h⁻¹` 和约 `1/5/20 kPa` 三档刚度等高精度断言，生成纪要没有给出支撑这些具体数值的来源。候选 4 的“图案保真度随诱导时序精度线性提升”同样是强函数关系，当前纪要没有对应证据。候选 2 的否定条件把“关灯后保持末态”直接等同于证伪，可逆重写的输入序列和期望回切状态没有定义完整。

**影响**：可证伪的外形已经具备，但范围一致性、数值依据和判别逻辑不足，未经选择与证据评审不能称为高质量假说。

**状态**：等待前端选择入口恢复。当前建议排除无细胞 TX-TL 候选，优先保留细菌纤维素光控候选并删除未经证据支持的“线性”限定；其他候选需先补齐来源与对照定义。

### P0：资料寻找已有合格产物，却因缺少终态写回被判失败

**现象**：资料寻找 Agent 分三批写回，所有成功写回的 `status` 都是 `running`。第三批之后它又进行了一次 DOI 搜索，然后单轮会话直接结束，没有再提交 `completed` 或 `needs_review` 终态。调度层随后把阶段任务标为 `failed`。

**矛盾证据**：同一任务记录同时满足以下状态：

- 顶层 `status=failed`；
- `completionGate.passed=true`；
- `result.materializedSources.status=completed`；
- `createdRecordCount=2`、`importedCandidateCount=2`，另有 4 条来源因去重而复用；
- `closureSummary.message=已生成 4 个原始资料，本阶段闭环成功`。

**影响**：后续资料提炼被阻塞，已经物化的有效来源无法继续流转。前端只能提供“重试资料寻找”，会重新调用模型和搜索，而不是对已有合格产物补做终态收口。

**状态**：未解决。已从前端执行唯一一次有界重试，仍未正常终态化；按验收约束不再消耗重复搜索预算。

### P1：知识搜集的部分冻结查询被目录 URI 污染

**现象**：8 条冻结查询中的 q005–q008 把 `challenge-question-catalog://...` 目录引用拼进搜索词，四条均返回 0 条可采信结果。Agent 后续使用正常英文补充查询才检索到资料。

**影响**：搜索预算被低质量查询消耗，延长资料寻找阶段，并降低反证和独立基线覆盖率。`searxng` 未配置会让该 provider 跳过，但 `ddgs` 仍可工作；它不是本次查询污染的根因。

**状态**：四类视角最终均有物化来源，但无效冻结查询仍造成补搜、回执绑定返工和上下文膨胀。

### P1：前端运行状态不会及时刷新

**现象**：4 个候选发言已有模型回执后，页面仍长时间显示 `0/4 位成员已发言`；手动整页刷新后才显示待人工确认和候选清单。

**影响**：操作者会误判讨论未执行，造成等待、重复操作或错误恢复。

**状态**：可通过刷新暂时恢复显示，但自动状态同步未通过验收。

### P1：资料寻找单次运行成本过高

**现象**：本次资料寻找会话执行 19 次迭代、22 次工具调用；会话汇总记录累计输入 661,266 tokens，最后一次模型上下文已达到约 77,067 输入 tokens。阶段工具自己的进度统计甚至累计到 88 次工具调用。

**原因证据**：一半冻结查询无效、补充查询命中大量跑题页面、两条候选因回执绑定失败再次搜索；上下文工具返回 35–40 KB 且多次提示截断，导致后续模型输入不断膨胀。

**影响**：对 6 条有效来源的寻找耗费明显偏高；失败后若直接重跑，成本与延迟会进一步放大。

**状态**：未解决。重试验收只允许一次，并检查是否复用现有来源。

本次唯一重试最终又读入 93,930 tokens，缓存命中率仅 15.6%，并在完成最后一轮绑定检索后触发 `context_budget_exhausted`。因此失败并非搜索不到资料，而是任务把大上下文、候选全文、搜索回执和多批写回持续累积到同一会话，在终态写回前超过硬上限。

### P0：错误 locator 进入候选层后，资料寻找角色没有可用的原位修正路径

**现象**：唯一一次重试已把资料物化到 10 条记录，并覆盖四类视角；第二批写回仍被 `source_search_receipt_missing` 拒绝，服务端列出 3 个 `unboundCandidates`。其中 Matter 生物塑料论文先前登记为 DOI `10.1016/j.matt.2024.10.018`，本次按题名执行一次 Crossref 权威查询，返回的实际 DOI 是 `10.1016/j.matt.2024.10.008`；同一候选层还存在 PII/展示 URL 形状不一致。

**根因证据**：资料寻找角色只能追加 `candidateLeads[]` 或排除 `invalidSources[]`，不能修改已物化候选的 locator。它即使补搜正确题名、正确 DOI 和出版方 URL，也无法使错误 DOI 的旧候选通过“每个候选都必须绑定真实搜索回执”的终态门。失败写回要求继续搜索缺失候选，形成搜索重试与数据修正职责错位。

**影响**：单条错误元数据可以让已经满足数量、视角和物化要求的整个阶段无法完成；继续搜索不能消除错误候选，因此会持续增加 token、搜索调用与延迟。

**状态**：未解决。本轮不再新增第二次前端重试；当前会话已直接以 `failed_runtime` 结束，并把错误候选修正能力列为修复入口。

### P0：失败写回发生部分数据提交，操作不具备原子性

**现象**：13:04 的第二批 `source_collection_stage_writeback_tool` 返回失败，报 `source_search_receipt_missing`；但候选仓仍新增了 3 条记录：正确 DOI 的 Matter 生物塑料论文、动态响应益生菌 ELM、Springer ELM 章节。任务顶层仍保留第一批的 `candidateCount=10` / `recordCount=10` 与旧摘要，没有反映这 3 条新增记录。

**影响**：同一个失败动作同时表现为“服务端拒绝”与“数据已写入”，使重试预算、候选计数、去重和恢复决策失去统一权威；下一轮重试会面对更多历史候选和更大的回执绑定面。

**状态**：未解决。修复时需要把候选物化和终态门禁放入同一事务边界，或者明确采用可恢复的预提交状态并由任务投影统一计数，不能继续让失败回执留下正式候选副作用。

### P0：上下文预算耗尽后没有机会执行合同要求的终态写回

**现象**：重试最后一次 `batch_web_search_tool` 已成功命中 Nature Communications 正文、PubMed 和 Europe PMC，用于绑定最后一个候选；紧接着模型下一轮调用在入口处因 `context_budget_exhausted` 被拒绝，系统直接写入 `turn_failed/failed_runtime`。Agent 没有机会调用合同指定的 `source_collection_stage_writeback_tool` 写 `completed`、`needs_review` 或 `blocked`。

**影响**：即使搜索和物化已经完成，阶段状态仍由会话运行失败覆盖，后续资料提炼不会启动。该失败模式在前端只能再次整体重试，无法从最后一个成功工具回执继续收口。

**状态**：已复现并停止继续重试。应在进入下一次模型调用前保留足够的终态写回预算，或由调度层在 completion gate 已满足时使用已有结构化回执完成确定性收口。

### P2：资料搜集状态与物化文件一度不一致

**现象**：阶段任务回执已经报告 `artifactComplete=true`、`source_records_ready`，并包含首批 4 条 `candidateLeads`；同一时刻该 source run 的 `candidates.jsonl` 与 `records.jsonl` 仍为空，正式运行继续报告 `knowledge_package_not_materialized`。

**影响**：阶段任务“已具备产物”和实际可供后续节点消费的物化结果之间存在时间差或状态语义混用。最终是否为缺陷需等搜集子流程终态后确认。

**状态**：已确认不是单纯时间差。任务后来确实创建或复用了 6 条来源，但顶层统计仍保持 `candidateCount=0`、`recordCount=0`，任务又被标为失败；这与 P0 的终态收口问题共同阻断后续节点。

## 尚未走到的前端闭环风险（静态代码证据）

以下项目因本次运行停在资料寻找与假说选择之前，未获得运行时复现，只作为后续验收必须覆盖的风险：

- `HypothesisFirstNodeInspector` 与 `ClaimBeliefGatePanel` 能显示“补齐或修订 claim 证据”的阻断信息和 evidence gaps，但没有补证 mutation、动作按钮或导航入口。若后续评审进入 claim 阻断，操作者可能仍无法从前端恢复。
- `NodeKnowledgeCollectionSection` 只提供 `ensure_knowledge_collection` / `inspect_knowledge_collection`，`KnowledgePackageReader` 也明确只读不代表审核或入库；当前未见把知识子运行结果吸收到父流程或据此创建修订的前端动作。
- 正式结果操作面覆盖 `record_program_review` 与 `create_formal_revision`，但完成态直接展示 H1–H4 通过，未见独立的 canonical result package 接收与核对入口。后续需要验证“状态完成”与“正式结果包已被操作者核验”是否被混为同一件事。

## 当前闭环判断

- **结构**：问题理解、候选生成、知识搜集、假说选择、评审和正式研究节点均有对应概念，但假说先行侧流与正式运行主流程的调度顺序和操作面没有解耦好。
- **效率**：模型按功能分级配置合理；查询污染、超长上下文、回执绑定返工、页面不自动刷新和主流程提前阻塞造成明显额外成本。
- **质量**：已经能生成具备机制、干预、读出和否定条件雏形的候选，但当前清单仍包含范围冲突和无证据的高精度断言，尚未达到可直接采用的高质量标准。
- **前端闭环**：不能。`hf_selection` 没有可操作表单，资料寻找失败后也只有整体重试入口；操作者无法选择候选、继续资料提炼或开启后续评审。

## 后续验收点

1. 修复资料寻找的终态收口、上下文预算和失败写回部分提交问题，再用隔离的新题验证五个知识节点可连续推进。
2. 修复 `hf_selection` 的操作面优先级，使所选节点能显示候选复选框和记录选择动作。
3. 对入选候选核对来源、替代解释、定量预测、证伪条件和资源可行性。
4. 只有评审收敛、正式结果包物化且前端能完成所有人工动作，才判定第一阶段有效闭环。
