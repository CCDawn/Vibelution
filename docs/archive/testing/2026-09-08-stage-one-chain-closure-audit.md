# 第一阶段链路集中修复与验收

目标：一次排清第一阶段可复现的代码与契约断点，集中修改后统一验证，再进行一次完整前端验收。范围仅包括假说形成及其知识子流程；不增加第二阶段模板，不降低真实原文要求，不按模型成本升级所有节点。

## 执行边界

- 停止逐补丁触发真实模型；只读活数据作为失败样本，不直接修改活任务或历史候选。
- 主 Agent 统一写入、审查、验证与集成。两个只读审查面分别为入口/候选/配置，以及来源任务/补源状态链。
- 每个缺陷必须有触发条件、最早错误来源、现有复用点和验证。无证据的可能性不制造防御代码。

## 已复现的集中修复项

| 缺陷 | 根因与影响 | 修复与证据 |
| --- | --- | --- |
| 诚实跳过原文后，证据卡构建仍失败 | 正式 claim 写回跳过 exclude/missing/unverified，artifact builder 却把这些条目按完整证据卡校验；混合成功与失败的批次不能交接 | 共享资格判断；生产 artifact builder 回归先失败后通过；全跳过仍被质量门拦住 |
| 合法 claims 写回在交接时丢失或失败 | builder 只遍历 keyFindings，忽略 claims；纯 claims 要求重复父 fact，双列表丢掉 claims | 同时读取两种既有结构，保留每条显式 fact，不用 summary 补事实 |
| 合法 flat 引文锚不被识别 | claim 物化接受 evidenceRefs 的 id+quote，builder 不认 id，只有额外 sourceRef 时才工作 | 引文引用的原始 id 作为 locator；不改逐字引文核验 |
| 写回先成功、结束后才因结构报错 | 写回边界只遍历可物化 claims，遗漏非法 keyFindings 形状/locator；builder 才拒绝 | 写回直接复用生产 card builder，提前返回具体字段错误；先失败后通过 |
| 成功抓取后上下文仍保留失败 | latest_failed_fetch_attempts 声称后项优先，但只累加 failed，不处理后续 fetched | 修复同源后续成功清除失败；补源复用此 helper，删除重复折叠代码 |

联合核验：证据交接/物化/逐字引文专项最终 41 项通过；结果包与证据关系专项 41 项通过。补源新额度测试已移除对 repair message 的桩，改用真实注册来源、真实任务存储、failed 抓取回执验证消息与新账本一并生效。

## 最终验收条件

1. 所有已确认的阻断缺陷有回归并修复；主 Agent 独立检查最终 diff。
2. 统一测试覆盖初次成功、来源不可达、补源成功、补好退出、额度边界和当前 run 身份；不通过旧回执或旧产物冒充完成。
3. 前端从候选操作到补源、真实证据、交接与假说结果包可完成；代码测试与真实模型运行证据分别记录。
4. 若外部来源全部不可达或研究质量不够，应明确停在可恢复状态并显示具体原因，不宣称高质量假说已经产生。
