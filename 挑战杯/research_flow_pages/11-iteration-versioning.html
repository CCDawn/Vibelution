输入research_loop / experiment_result_pack

输出research_loop / evidenceRecords

当前节点规划

本页只展示 11 节点。通过左侧导航可进入其它节点页。

目标

管理候选修订、拒绝原因、同类假设合并和下一轮实验建议，同时保持候选版本账本与正式知识/RAG/official graph 的边界。

输入

  • research_loop
  • experiment_result_pack
  • candidateIds
  • review_record
  • versionHistory
  • ingested 知识状态

处理动作

  • Iteration Planner Agent 使用 challenge_cup_iteration_context_tool 读取 Research Loop、实验计划和证据缺口。
  • Iteration Planner Agent 使用 challenge_cup_iteration_writeback_tool(create_loop/record_evidence/record_decision) 写入 Research Loop 账本。
  • Candidate Versioning Agent 使用 challenge_cup_versioning_context_tool 读取 candidate_versions/index.json 中的 versionHistory、relations 和 rejectionArchive。
  • Candidate Versioning Agent 使用 challenge_cup_versioning_writeback_tool(record_version/supersede/derive/reject) 维护候选版本链。
  • 强制边界：不自动应用迭代决策，不写正式知识，不写 RAG，不写 official graph，不创建训练任务。

输出物

  • research_loop
  • evidenceRecords
  • decision
  • iterationProposal
  • candidate_versions/index.json
  • versionHistory
  • relations
  • rejectionArchive

风险

  • 同类假设重复
  • 拒绝原因丢失
  • 正式知识与候选版本混淆
  • 迭代 Agent 被误授搜索、代码执行或正式知识写入工具

未决事项

  • 版本治理当前是轻量账本，不替代后续正式 ExperimentResult schema 或交付材料版本库。
