Research Flow Node 07

知识治理入库

steward_pack_draft 先作为团队待入库知识包暂存，搜集流程向 Knowledge Steward Agent 发送入库请求并唤醒它处理最终入库。

待知识治理审查Knowledge Steward Agent · agent-knowledge-steward独立计划页
输入review_record 候选 / algorithm_hypothesis 候选
动作校验 candidateIds、targetDomain、sourceTrace、riskSummary、proposalPayload、ratingSuggestion。
输出steward_pack_draft 候选 / knowledge_steward_inbox_request
记忆/图谱审批通过后正式 KnowledgeItem metadata 记录 officialResearchGraph；状态总览明确 candidate_graph_preview_only 与 official_research_trace_synced 的边界。

当前节点规划

本页只展示 07 节点。通过左侧导航可进入其它节点页。

目标

把待治理候选整理为可审查的 SourceArtifact、pending RefinementProposal 和可选 pending ratingSuggestion。

输入

  • review_record 候选
  • algorithm_hypothesis 候选
  • candidate_graph 快照
  • 目标知识域

处理动作

  • 校验 candidateIds、targetDomain、sourceTrace、riskSummary、proposalPayload、ratingSuggestion。
  • 强制 approvalRequired=true，禁止 officialSync、applyNow 或 writeOfficialGraph 等立即正式写入意图。
  • 合格草稿先进入 steward_pack_draft，作为团队提炼后的待入库知识包暂存。
  • 知识搜集入库入口默认向 Knowledge Steward Agent inbox 发送 challenge_cup_knowledge_ingestion_request 并尝试唤醒该 Agent。
  • Knowledge Steward Agent 收到请求后再提交 Team Knowledge 待审队列，进入 steward_pending_knowledge_review。
  • Ingestion Approval Gate 批准后进入 official_synced；拒绝后回到 steward_needs_revision。
  • 审批通过且创建正式 KnowledgeItem 后，将 proposal 级 pending ratingSuggestion 迁移为 KnowledgeItem 级 pending ratingSuggestion。
  • 审批通过后把 sourceTrace / candidateIds 转为 KnowledgeItem metadata.officialResearchGraph 中的 supports、maps_to、inspires、approved_for_ingestion 正式边。
  • GET knowledge-ingestion/status 聚合 CandidateStore、校验报告、候选图摘要和 Team Knowledge stats，输出 stages、actionItems、officialBoundary。
  • Teams 工作台同时读取 coordination/status，把待转移、待返工、待治理和阻塞候选集中显示，并展示目标功能 Agent 与建议通道；不提供自动调转或自动发送按钮。

输出物

  • steward_pack_draft 候选
  • knowledge_steward_inbox_request
  • SourceArtifact
  • pending RefinementProposal
  • proposal ratingSuggestion
  • KnowledgeItem ratingSuggestion
  • officialResearchGraph
  • official_sync_record
  • knowledge_ingestion_status
  • coordination_status_panel

风险

  • 绕过审批门禁
  • 目标知识域错误
  • 把 ingestion pack 草稿误当正式入库记录

未决事项

  • 是否把 knowledge-ingestion/status 接到 Teams 前端状态漏斗与告警徽标。

记忆与图谱边界

区分候选工作区、知识治理 Agent、正式 Team Knowledge 和正式知识图谱。

候选状态待知识治理审查
记忆平台待入库包通知阶段不创建正式 KnowledgeItem；Knowledge Steward Agent 后续审批通过后复用 Team Knowledge review/apply 创建正式 KnowledgeItem；状态总览只读聚合 formalKnowledgeItemCount、pendingProposalCount 和 Agent 通知结果。
图谱同步审批通过后正式 KnowledgeItem metadata 记录 officialResearchGraph；状态总览明确 candidate_graph_preview_only 与 official_research_trace_synced 的边界。

可跑通节点契约

这一块只覆盖知识搜集、筛选和入库 MVP，不涉及实验训练或交付实现。

状态steward_pending_knowledge_review
功能岗位Knowledge Steward Agent / agent-knowledge-steward
Agent 状态后端草稿包门禁、Team Knowledge 待审入库桥、审批门禁和入库状态总览已接入
进入条件review_record 或候选图谱已给出可追溯 candidateIds，且具备目标知识域。
退出条件合格草稿提交后进入 steward_pending_knowledge_review；批准后进入 official_synced、记录 officialSyncRecord 和 officialResearchGraph，并创建 KnowledgeItem 级 pending ratingSuggestion；status=ready 表示入库链路已跑通。
审核门禁必须经 Knowledge Steward Agent / Ingestion Approval Gate 确认，不能由科研执行 Agent 或本地模型直接入库。

本步操作

生成带 sourceTrace、riskSummary、proposalPayload、ratingSuggestion、approvalRequired=true 的 CandidateStore 草稿包，并可提交到指定 knowledgeBaseId 的待审入库队列；status API 汇总 pendingProposalCount、formalKnowledgeItemCount、actionItems 和 officialBoundary。

本地研究模型用法

本地 9B 模型只能生成 steward_pack_draft 草稿，正式建议仍由 Knowledge Steward Agent 检查；禁止在输出中请求正式写入。

所需功能

  • proposalPayload
  • ratingSuggestion
  • approvalRequired=true
  • SourceArtifact
  • pending RefinementProposal
  • KnowledgeItem rating suggestion migration
  • knowledge_ingestion_status
  • officialResearchGraph
  • officialSyncRecord
  • official write 禁止项

工具/平台能力

  • knowledge_governance_tasks_tool
  • knowledge_steward_workbench_tool

  • knowledge_proposal_tool
  • knowledge_ingestion_tool

功能缺口

pending ratingSuggestion 到正式 KnowledgeItem rating review 的承接已接入；正式边已写入 officialResearchGraph；status API 和 Teams 前端状态漏斗已能显示 pending/ready/actionItems。后续可补按候选/知识库筛选。

失败回退

缺必填治理字段、approvalRequired 非 true，或包含 officialSync/applyNow/writeOfficialGraph 时返回 steward_needs_revision。
