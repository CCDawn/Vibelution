# 《Science》125题执行协议

更新时间：2026-07-21

## 1. 目标与边界

本协议用于生成挑战杯 XH-202619 方向 A 的全量逐题输出。官方页面隐藏的“作品提交要求”明确写明：如选择方向 A，需提交智能体框架在全部 125 个科学问题的输出结果文档。

这不意味着必须声称已经解决 125 个科学问题，也不意味着每题都必须完成真实实验。每题输出的职责是：准确理解问题，建立可追溯证据，生成并比较可证伪假设，给出可执行研究计划，记录反馈修订和人类审批；未执行的实验必须明确标记为“计划”，不得伪造结果。

事实源：

- 赛题页：<https://university.aliyun.com/action/tzbjbgs2026>
- 官方题册：<https://www.science.org/cms/asset/b09620dc-2937-45bd-9c29-3ea07c1f4a04/sjtu-booklet.pdf>
- 本地规范化清单：`data/science_125_questions.json`
- 单题输出 Schema：`schemas/challenge_question_output.schema.json`

## 4. 单题科研流程

```text
锁定英文原题
  -> 问题拆解与范围声明
  -> 人类门控 H1：确认问题理解
  -> 检索并登记支持证据、反证和边界证据
  -> 生成至少两个机制不同的候选假设
  -> 七维独立审查，不生成总分
  -> 人类门控 H2：基于权衡选择候选假设
  -> 生成研究计划、控制组、失败标准和停止条件
  -> 人类门控 H3：批准研究计划
  -> 根据新增证据、模拟结果或人工反馈至少修订一轮
  -> 人类门控 H4：批准对外输出
  -> Schema、引用和哈希校验
```

### H1 问题理解

确认研究对象、时间尺度、空间尺度、适用学科、关键术语、隐含假设和明确不回答的范围。英文原题不可改写；中文译文仅作展示字段。

### H2 假设选择

每个候选假设分别检查：

1. 证据充分性；
2. 科学事实准确性；
3. 创新性；
4. 可证伪性；
5. 研究计划可执行性；
6. 风险与伦理；
7. 反例和边界覆盖。

禁止把七个维度压缩成一个总分。候选选择采用“多维 Pareto 比较 + 人类书面决策”；低分维度、冲突证据和淘汰理由必须保留。

### H3 研究计划

计划至少包含目标、方法、工作包、变量、控制组、数据与材料、分析方法、成功标准、失败标准、停止条件、资源、时间线和风险。涉及人体、动物、危险材料、隐私数据或高成本实验时，只能给出合规研究计划，不得默认授权执行。

### H4 对外输出

审查引用是否真实、结论是否越界、实验是否实际执行、模型与平台证据是否齐全、失败和不确定性是否保留。只有 H4 为 `approved` 的结果可以进入正式汇总文档。

## 5. 最小合规输出

每题至少满足：

- 1 条原始英文问题和稳定 `SCI-xxx` ID；
- 清晰的问题范围、子问题、假设和未知项；
- 至少 4 条可访问证据，其中至少 2 条为同行评议论文、权威数据集、标准或官方材料；
- 至少 1 条挑战性证据、反例或边界证据；
- 至少 2 个机制不同、可证伪的候选假设；
- 每个候选假设完成七维独立审查；
- 1 个经人类审批的候选假设和完整研究计划；
- 至少 1 轮由新证据、审查意见、模拟结果或人工反馈触发的修订；
- 明确的结论边界、局限和下一步验证动作；
- Qwen 模型标识、阿里云百炼或官方工具调用证据；
- Schema 校验、引用校验和输出哈希。

若资料不足，不得用模型常识补齐为事实。输出应进入 `blocked` 或 `needs_revision`，并记录缺失信息。

## 6. 广度与深度分层

### 全量广度层

125 题全部达到“最小合规输出”。大多数问题交付的是经过证据约束的候选假设与研究计划，不声称已经完成实验或解决问题。

### 代表性深度层

从不同领域选择 3 个案例，补充真实数据、计算实验、虚拟仿真或已有实验反馈闭环。深度案例用于证明平台具备“计划可执行、结果能改变下一轮假设或计划”的能力，不能替代其余 122 题的输出。

建议组合：

- 1 个与当前 FashionMNIST 预测编码实验链路可诚实对齐的问题；
- 1 个可使用公开数据完成计算验证的问题；
- 1 个跨学科问题，用于展示证据冲突、人类门控和研究计划修订。

## 7. 批处理与账本

采用每批 5 题、共 25 批的方式推进。单批完成后再开启下一批，避免在证据协议尚未稳定时一次性污染全部结果。

建议目录：

```text
outputs/science-125/<run-id>/
  manifest.json
  batch-ledger.jsonl
  questions/
    SCI-001.json
    SCI-002.json
    ...
  reports/
    all-125-summary.md
    representative-cases.md
```

`batch-ledger.jsonl` 每行至少记录：`question_id`、`status`、`attempt`、`started_at`、`completed_at`、`model_id`、`schema_validation`、`citation_validation`、`human_review_status`、`output_path`、`failure_code`。

失败必须显式入账，不允许跳过后仍把批次标为完成。重试不得覆盖上一版输出，应通过新的 `run_id` 或修订记录保留差异。

## 8. 提交汇总原则

- 125 题结果文档是机器输出证据包，不应全部塞入 20 页主 PDF。
- 主 PDF 展示流程、质量控制、领域覆盖、统计摘要和 3 个深度案例。
- 全量逐题结果作为单独附件或可访问结果文档提交，并提供索引、版本号和哈希。
- API 与前端必须能按 `question_id` 查询原题、证据、候选假设、研究计划、反馈版本和审批状态。
- 对外统计只能基于已通过 Schema 与引用校验的记录；不得把 `blocked`、`failed` 或待审批记录计入完成数。

## 9. 批处理启动门槛

在运行第一批之前必须完成：

1. 阿里云百炼 Qwen 模型与调用证据字段确认；
2. 单题样例通过 Schema 校验；
3. 引用抓取、去重和可访问性检查可运行；
4. 四个人类门控有明确审批人或审批队列；
5. 输出目录、版本规则和失败重试策略已固化。

未满足以上门槛时，只允许生成样例草稿，不得启动 125 题正式批处理。
