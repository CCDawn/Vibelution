# 挑战杯赛题对齐方案

更新时间：2026-06-10

## 1. 对齐结论

当前方案不需要推翻，应该继续作为 Vibelution 挑战杯项目的工程主线。

对齐后的参赛定位为：

**Vibelution-Scientist：基于 Qwen 的证据图谱驱动 AI Scientist，面向神经科学/脑语言机制启发的神经网络算法发现。**

主赛道选择：

- 主赛道：赛道一-2，科学机制推理与证据链迭代验证。
- 支撑能力：赛道二-1，知识图谱构建与证据推理。
- 加分扩展：赛道一-3，科学实验自主任务规划与反馈优化。

当前 01-09 流程已经覆盖“资料进入工作区 -> paper_note -> neuro_mechanism -> mechanism_mapping -> algorithm_hypothesis -> review_record -> steward_ingestion_pack -> candidate_graph -> official_graph”的核心链路。需要补齐的是官方赛题外壳、Qwen/百炼凭证、10-12 的实验和交付闭环。

| 科学问题理解 | 01 资料工作区、02 paper_note | 增加明确研究问题：神经科学/脑语言机制如何启发 Agent 自进化与算法发现 |
| 知识整合 | 02 paper_note、03 neuro_mechanism、07 steward_ingestion | 保留 sourceRef、pageAnchor、citation、sourceTrace |
| 关联发现 | 04 mechanism_mapping、08 candidate_graph | 强调从神经机制到计算抽象的 factLayer/inferenceLayer |

## 4. 推荐研究问题

第一版不要把问题铺得太大。建议锁定一个可演示、可验证的问题：

**人脑语言理解中的预测编码、误差修正与记忆回放机制，能否启发 AI Agent 自进化过程中的经验选择、错误修正和算法假设发现策略？**

候选核心假设：

**基于预测误差和优先经验回放的经验调度策略，相比随机回放或时间顺序回放，能在同等 token / 时间预算下提高 Agent 生成高质量算法假设和修复错误的效率。**

这条问题能同时连接：

- 神经科学文献：预测编码、海马回放、优先记忆访问、误差修正。
- Vibelution 机制：Trace、Score、Critic、Evolver、Case、Attempt。
- 可验证实验：随机回放 vs 时间顺序回放 vs 优先回放。

## 5. 评分对齐策略

### 科学价值 40%

拿分方式：

- 研究问题必须是明确的科学/算法问题，而不是“做一个平台”。
- algorithm_hypothesis 必须给出可证伪条件。
- review_record 必须包含支持证据、反对证据、边界条件和过度类比风险。

验收口径：

- 至少 1 个完整假设链路：source -> paper_note -> neuro_mechanism -> mechanism_mapping -> algorithm_hypothesis -> review_record。
- 每条关键结论必须有 sourceRef/pageAnchor/citation。
- 至少 1 个假设被反例复核后修订。

### 技术深度 30%

拿分方式：

- 展示多 Agent 分工：Source Intake、Paper Note、Neuro Mechanism、Mechanism Mapping、Algorithm Hypothesis、Evidence Review、Knowledge Steward。
- 展示候选图谱和正式图谱边界。
- 接入 Qwen/百炼，不只用本地 qwen3.5-9b。

验收口径：

- Qwen/百炼调用链有截图、日志、模型配置。
- CandidateStore schema 校验能拦截缺 citation、缺实验计划、过度类比未标记等问题。
- candidate_graph 能展示 missingLinks、unreviewedNodes 和 officialBoundary。

### 应用潜力 30%

拿分方式：

- 输出可以复用到科研选题、算法发现、论文写作和专利挖掘。
- 提供最小实验闭环，而不是只给研究计划。
- 提交材料可复现。

验收口径：

- 10 experiment_loop 至少跑通 1 个 smoke 实验。
- 12 delivery 能导出官方字段齐全的技术方案。
- 代码、配置、输入样例和结果记录能一起打包。

## 6. 必补缺口

当前方案已经有工程骨架，但还缺 5 个面向比赛的硬证据：

1. 官方 Qwen/阿里云百炼调用证据。
2. 明确的参赛主问题和作品名称。
3. 至少一个完整、无断链的候选证据图谱。
4. 至少一个最小实验验证结果。
5. 官方 PDF 输出字段的交付模板。

官方 PDF 输出字段建议固定为：

- Problem Statement
- Rationale
- Technical Details
- Datasets
- Paper Title
- Paper Abstract
- Methods
- Experiments
- Results
- References

## 7. 近期推进计划

### P0：赛题定位锁定

时间：2026-06-10 至 2026-06-12

交付：

- 作品名。
- 主赛道说明。
- 研究问题。
- 核心假设。
- 官方评分对齐摘要。

退出标准：

- 所有页面和交付材料统一使用“AI Scientist / 可验证科学假设生成 / 神经机制启发算法发现”表述。
- 不再混用网络安全靶场或泛 Agent 平台作为主线。

### P1：Qwen/百炼合规接入

时间：2026-06-13 至 2026-06-20

交付：

- Qwen/百炼调用配置。
- 至少 3 个节点的调用样例：paper_note、mechanism_mapping、algorithm_hypothesis。
- 调用截图与日志。

退出标准：

- 12 delivery 页面可以列出阿里云模型调用证据。
- 本地模型保留为草稿生成/批处理模型，官方模型用于关键节点定稿或复核。

### P2：打通无断链证据链

时间：2026-06-21 至 2026-07-10

交付：

- 1 条完整 source -> official_graph 链路。
- candidate_graph qualityStatus 从 broken_links 收敛到可解释状态。
- review_record 包含反例与风险。

退出标准：

- 每个 algorithm_hypothesis 能追溯到机制、论文、页码和审稿记录。

### P3：实验验证闭环

时间：2026-07-11 至 2026-08-10

交付：

- baseline：随机回放或时间顺序回放。
- candidate：预测误差/优先经验回放策略。
- metric：成功率、平均尝试次数、token 成本、修复质量、假设质量评分。
- smoke 实验结果。

退出标准：

- 至少一个结果可以支撑“方案可落地验证性”。
- 实验失败也要有失败原因和下一步修订。

### P4：提交材料收束

时间：2026-08-11 至 2026-09-03

交付：

- 20 页内技术方案 PDF。
- 源代码与复现说明。
- 可交互演示页面。
- 10 分钟内演示视频。
- 阿里云模型调用凭证/截图。

退出标准：

- 提交包能解释：科学问题是什么、为什么有价值、AI Scientist 怎么工作、生成了什么假设、怎么验证、结果能否复现。

## 8. 对齐后的主叙事

对外不要说：

“我们做了一个知识库、一个 RAG、一个团队协作系统。”

对外应该说：

“我们构建了一个基于国产大模型的 AI Scientist 原型。它以神经科学文献和脑语言机制为输入，通过多 Agent 协作完成文献事实抽取、机制发现、计算抽象、算法假设生成、反例复核和实验计划生成，并用证据图谱保证每个科学假设可追溯、可审查、可验证。”

阶段决策：advance。

当前方案已经足够支撑主赛道选择，下一阶段不应继续泛化赛道，而应围绕“赛道一-2 + 赛道二-1 底座”补齐官方模型调用、完整证据链和最小实验结果。
