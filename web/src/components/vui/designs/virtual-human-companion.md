# Virtual-human companion surfaces

## 功能

人物大厅与原生聊天中的人物栏共同表达一个持续生活的虚拟人。大厅负责进入人物；聊天左栏只展示当前人物，不承担切换器职责。消息历史、Composer、流式回复和主动消息继续由 Direct Session 链路拥有。

## 适用范围

- `/companions`：桌面人物大厅；每位已启用虚拟人插件的 Agent 展示为一张大幅人物卡。
- `/chat?session=…&companion=…`：原生聊天的当前人物左栏。
- 右侧生活栏：当前活动、地点与移动、情绪余波、生活节律、可选具身化回退、来源可追溯的环境事实、长期日历、个人目标、兴趣成长、经历、本地生活动态、主动消息判断、关系、NPC 社会圈、熟悉地点/物品、夜间回想、待审核变化、长期记忆，以及可审阅的陪伴偏好卡。
- 生活档案：首次启用前从受控目录选择城市与学生/员工/自由职业/待业/退休身份；启用后右栏展示可编辑草案，确认后投影学校或单位、作息、物品、账户和周期收支，并提供配对生活管家的原生 Session 入口。

不适用于普通 Agent 列表、团队成员选择器或第二套聊天页面。

## 使用方式

- 大厅卡片与聊天左栏必须复用 `CompanionPortrait`，图片来源统一为 Agent 的 `avatarImageUrl`；不得按显示名硬编码人物图片。
- 大幅透明立绘使用 `object-contain` 和底部对齐；圆形小头像才使用面部裁切。
- 大厅卡片使用真实 `personaProfile`、插件 snapshot、日程与关系摘要。无数据时显示明确的空状态，不编造经历、关系或时间。
- 进入人物调用 `openCompanionSession`；设置页返回目标包含原 `session` 与 `companion`，以回到同一条会话。
- 普通 `/chat` 的恢复候选、Session 标签与引用列表排除明确带 `virtualHumanCompanion` 标记的人物会话；旧通知或历史链接若只带人物 `session`，必须由 Companion 适配层补齐 `companion` 身份后再展示，不得落入普通聊天外观。
- 人物大厅从原生 Session summary 投影最新完成身份；未读只使用共享 `sessionActivityIndicator` 的本地已读标记，不复制 transcript 或把人物放回普通会话栏。点击人物或显式 Companion 通知后，使用同一完成身份清除大厅未读。
- 对话左栏不放人物选择器。切换人物需返回人物大厅。

## 布局与状态

- 桌面大厅使用单列大卡：文字与生活摘要在左，人物立绘在右；窄窗口可上下堆叠。
- 对话左栏以大幅人物立绘为主体，底部只保留在线/本地时间、名字、当前活动，以及地点/活动/关系三项图标摘要；身份说明、人物自述、完整档案说明和切换人物提示不在聊天主画面重复出现，设置入口保留为图标按钮。
- Companion 对话顶部展示当前人物圆形头像、名字、在线/当前活动与主动联系入口；普通 Session tab 区不显示这组人物头部。
- 人物生成回复但尚未输出正文时，只显示一个“正在输入…”；它复用助手消息的居中轨道、保留当前人物的圆形头像，并从头像右侧正文列起始，不展示内部推理、工具过程或第二种状态。
- Companion 模式的中栏顶部使用既有 `VPopover` 提供当前人物的主动联系快捷设置：`安静 / 自然 / 活跃` 三档与启用开关；自然档默认每天 10 次、最短间隔 60 分钟，完整免打扰和自定义数值继续由 Agent 插件设置拥有。普通 Agent 不出现该入口，聊天面也不展示技术队列。
- Companion 模式的 Composer 只保留消息输入、附件与发送行为；模型/推理档位、Token/缓存环、Agent 权限、心智快照和斜杠指令提示均在人物展示层隐藏。普通 Agent 的同一组控件保持原样。
- loading、error、empty、paused 和 avatar 缺失均使用现有 VUI 状态与回退。
- 人物有未读完成消息时，在生活状态旁显示单个高对比“有新消息”胶囊；它是当前 Session 最新完成身份的视觉提示，不显示推理、工具状态或伪造精确消息数。
- 关系、日记和生活事件只读展示服务端事实；原始对话历史仍由当前 Session 所有。
- “现在”首屏顺序为场景卡 → 心情图标与体力/社交仪表 → 下一项安排；生活节律、环境、主动开口判断、关系连续性和呈现/表达进入“更多生活细节”。技术状态必须翻译成自然语言，不把内部决策码直接暴露给用户。语音、Live2D 或 3D provider 不可用时安全回退到现有立绘，且不得阻塞文字对话。
- 未确认的生活草案在“现在”首屏用视觉卡展示城市、身份、学校/单位、物品与虚构资产，并只允许通过 VUI 表单编辑有界字段；有未保存修改时不能确认。确认成功后同一卡片切为只读事实，并用“生活管理”打开绑定中精确记录的隐藏管家 Session。该按钮只回调 Chat 路由 owner，不自行拼接 URL，也不把管家恢复到普通会话目录。
- “今天”首屏显示视觉时间轴与个人目标；长期日历、兴趣成长、实际经历、未完话题和本地生活动态进入渐进展开区。计划只能解释意图，只有实际完成事件才能推进目标、兴趣或进入生活动态/记忆。
- “记忆”首屏以回忆卡片、自我人生线和关系摘要为主；夜间回想、待审核变化、关系、社会圈、地点/物品和日记进入渐进展开区。自我人生线复用原生 Agent episodic memory，记忆强度可展示重要性、情绪余波、未完话题和回想强化的派生分数，但不得成为第二套记忆存储。
- 陪伴偏好卡只展示当前 Agent 原生 episodic memory 中用户确认或操作员审核过的结构化偏好；称呼、回答长度、追问频率、幽默、主动联系、兴趣和隐私偏好可在卡内纠正或删除。纠正使用原生 supersede 保留历史，插件 receipt 不保存偏好正文；卡片不得读取 Life World 或普通 Session transcript 作为第二画像源。
- 大厅、聊天左侧人物栏和会话头复用同一个 `CompanionPortrait`；只消费 Task 34 的 `expressionId / motionPreset / blinkProfile / sceneKey / assetRefs` 做轻量表情、呼吸、眨眼和场景反馈。授权表达/背景资产加载失败时按顺序回退 Agent 原头像和姓名首字母；`prefers-reduced-motion` 禁止非必要动画。原生消息头像与单一“正在输入…”继续由会话组件拥有，不复制、不替换，也不读取推理或工具过程。
- 夜间回想只展示经过人工/操作员审核为 `approved` 且通过来源校验的提案；`pending` 只能显示为“待审核的变化”，不能进入 Prompt、人格或记忆。梦境、计划或无来源推断不得显示为外部事实。NPC 只是人物生活中的轻量档案，不创建 Agent。环境事实同时显示来源类型，来源引用保留在可访问的 `title` 中。
- “待审核的变化”使用现有 `VButton` 提供批准与拒绝；操作只调用 Agent-scoped `reviewReflectionProposal` command，以当前 `stateVersion` 防止覆盖并发生活变化，并用稳定幂等键避免重复审核。虚拟人的 Agent 工具只能提出提案，不能调用该审核动作。

## 交互与无障碍

- 主动作使用 `VButton`，站内档案跳转使用 `VRouteLinkButton`，状态使用 `VStatusChip`，主动联系快捷设置使用 `VPopover` + `VCheckbox`；不得引入第二套浮层或表单控件。
- 人物图像有包含人物名的可访问标签；装饰光晕、网格和状态点不进入读屏顺序。
- 主卡不嵌套可点击卡片；进入房间与查看档案保持两个清晰的焦点目标。
- Companion 桌面通知由独立适配器观察隐藏 Session，点击只调用 `openCompanionSession(sessionId, companionAgentId)`；普通通知 payload 和普通 `openSession` 路径保持不变。
- 桌面目标视口至少检查 1600×900 与 1280×760，并验证文本截断、焦点、图片裁切和 console。
