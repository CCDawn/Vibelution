# 团队流程工作台

## GenericWorkflowWorkspace

### 功能
使用真实团队和流程定义配置输入、顺序步骤、负责人，或查看运行快照、人工确认与产物。

### 适用范围
团队流程工作区；显式原生会话、既有研究记录及来源收集仍由原路由承载。复用 VUI 产品 API、VCanvasWorkbenchPage 与 WORKBENCH_LAYOUT_IDS.teams；不引入第二套布局、状态或 transcript。

### 使用方式
由 GenericTeamWorkspaceRoute 传入真实团队与导航回调，useWorkflowWorkspace 持有服务端流程、草稿及运行权威。开始运行仍先保存并冻结定义；团队/流程切换关闭旧启动快照；停止、重试与确认沿用原命令。

## WorkbenchShell

### 功能
左侧流程/成员列表、中央主区及右侧节点配置。团队标题、主区标题和配置标题在桌面同一高度；工作区标题栏固定 52px，不再挂常驻副标题，也不叠加外层标题和面板间距。全局导航由 App shell 持有，本组件不新增一套导航。

### 适用范围
编辑、运行、加载、失败与无流程状态。无流程时隐藏保存状态、工作模式、保存和试运行。loading/error 不展示模板起步页。

加载时保留正式框架：显式 `teamWorkspace=flows` 的首屏路由占位、团队元数据读取和流程读取复用同一个 WorkbenchShell，始终撑满可用高度，沿用实际栏宽记忆、52px 标题栏和响应式抽屉。未知数据用 VSkeleton 原位占位，不展示“还没有流程”或虚假的成员数量；已知流程保留真实编辑器及 Inspector。首屏占位不可交互，保存/试运行在流程读取期间禁用。

### 使用方式
使用 VCanvasWorkbenchPage 的 embedded chrome；侧栏默认 224px、检查栏默认 312px，沿用共享尺寸持久化。窄屏由 recipe 转为抽屉，Inspector 自身标题在抽屉中隐藏以避免重复。所有新建、成员、讨论、历史、保存和运行操作都回调既有 owner；停止 pending/stopRequested 必须防止重复提交。

## WorkflowWorkspaceLoading

### 功能
在页面模块和团队数据读取期间立即呈现真实 WorkbenchShell，保持全高、顶部、侧栏及底部成员区的实际几何关系。

### 适用范围
显式流程路由的首次加载与 GenericTeamWorkspaceRoute 的元数据读取；不替代普通团队讨论页的既有加载框架。

### 使用方式
只组合 WorkbenchShell 与 VSkeleton，不复制页面布局或维护另一套尺寸。数据未确定前不声称流程为空或成员为零，加载框架不可交互；静态起步内容的占位复用 WorkflowStart 实际标记。共享样式随 App shell 提前加载，避免等待 Teams CSS 时退化成无布局内容。

## WorkflowStart

### 功能
展示现有模板和空白创建入口，帮助用户直接理解输入、协作和交付。

### 适用范围
成功读取后的无流程状态。模板卡片不直接写数据；选择模板后预填现有创建弹窗，确认后才添加草稿。

### 使用方式
模板名称、说明、步数和步骤标签均从 workflowTemplates 的同一份定义派生；不在 UI 复制模板数据。桌面双列、窄屏单列，内容靠上、限宽、左对齐。复用 VButton，现成模板可编辑，空白流程不预置业务字段。

首屏占位复用同一份卡片与文字布局，在真实文字边界内显示 VSkeleton；不另建固定高度的假画板。占位内容从可访问树隐藏，并禁用创建操作，直到流程列表确认。

## FlowEditor

### 功能
按顺序展示节点、负责人、执行要求和状态，选择节点后直接编辑或查看运行详情。

### 适用范围
当前顺序流程；不提供分支或循环的假象。普通 Agent、人工确认、输入和交付采用图标及文本，状态不能只靠颜色。

### 使用方式
使用 ol/li 和 VNativeButton 绘制单列节点，顺序号与连接线保持阅读方向。中央内容滚动，节点卡片最大宽度受限，长名称/说明截断但保留可访问名称与配置全文。颜色与字号沿用 VUI 语义 token，支持浅色和深色；顶部保存为桌面主要保存入口，窄屏检查栏保留保存入口。

## 验证边界

验证空白、加载、失败、模板创建、节点编辑、保存反馈、运行停止状态及桌面/窄屏布局；真实模型执行与发布属于另外的验收面。

## WorkflowInspectorFrame

### 功能
统一节点配置和运行详情的容器、52px 标题、滚动正文与底部操作区域。

### 适用范围
正式 Inspector 和读取占位；宽度仅由 WORKBENCH_LAYOUT_IDS.teams 的共享 pane persistence 决定。

### 使用方式
消费 title/detail、children 和 footer。加载与完成使用相同 DOM 和样式，窄屏均由原 recipe 转为抽屉。

## WorkflowDesignFields

### 功能
复用实际步骤名称、输入卡片和执行要求表单，读取期间通过 VSkeleton 覆盖原控件。

### 适用范围
设计页与只读加载提示；select 类型的额外选项框也保留占位。

### 使用方式
业务数据和修改回调由工作台传入。占位值不进入真实草稿或 API，整个加载框架 inert 且从可访问树隐藏。

## WorkflowDesignFooter

### 功能
统一桌面保存反馈、窄屏保存入口与步骤操作的几何结构。

### 适用范围
设计与加载状态。

### 使用方式
加载仅覆盖保存反馈，不声称已保存，所有动作由上层加载框架阻止。

## WorkflowInspectorLoading

### 功能
组合真实 InspectorFrame、DesignFields 和 DesignFooter，为编辑页预留配置栏及输入卡片。

### 适用范围
已读取过的已保存流程再次进入、刷新和团队数据读取。

### 使用方式
同源浏览器仅保存按团队隔离的步骤类型、输入类型和流程数量，最长30天、最多20个团队；不存正文、名称、输入值、成员标识、流程ID或面板尺寸。只决定占位结构，后端成功响应始终覆盖提示，空结果回到起步页，禁用或损坏存储不阻止读取。首次无提示时先保留中性编辑器和配置栏；只在成功确认空列表后切换起步页。无历史时节点与输入数量为中性占位，后端响应到达后按实际结构替换。FlowEditor 复用真实节点并覆盖其内容；三个加载阶段均消费相同结构提示，避免中途切回起步页。
