# 团队流程工作台

## GenericWorkflowWorkspace

### 功能
使用真实团队和流程定义配置输入、顺序步骤、负责人，或查看运行快照、人工确认与产物。

### 适用范围
团队流程工作区；显式原生会话、既有研究记录及来源收集仍由原路由承载。复用 VUI 产品 API、VCanvasWorkbenchPage 与 WORKBENCH_LAYOUT_IDS.teams；不引入第二套布局、状态或 transcript。

### 使用方式
由 GenericTeamWorkspaceRoute 传入真实团队与导航回调，useWorkflowWorkspace 持有服务端流程、草稿及运行权威。开始运行仍先保存并冻结定义；团队/流程切换关闭旧启动快照；停止、重试与确认沿用原命令。

## WorkbenchShell

### 功能
左侧流程/成员列表、中央主区及右侧节点配置。团队标题、主区标题和配置标题在桌面同一高度；工作区标题栏固定 52px，不再挂常驻副标题，也不叠加外层标题和面板间距。全局导航由 App shell 持有，本组件不新增一套导航。

### 适用范围
编辑、运行、加载、失败与无流程状态。无流程时隐藏保存状态、工作模式、保存和试运行。loading/error 不展示模板起步页。

### 使用方式
使用 VCanvasWorkbenchPage 的 embedded chrome；侧栏默认 224px、检查栏默认 312px，沿用共享尺寸持久化。窄屏由 recipe 转为抽屉，Inspector 自身标题在抽屉中隐藏以避免重复。所有新建、成员、讨论、历史、保存和运行操作都回调既有 owner；停止 pending/stopRequested 必须防止重复提交。

## WorkflowStart

### 功能
展示现有模板和空白创建入口，帮助用户直接理解输入、协作和交付。

### 适用范围
成功读取后的无流程状态。模板卡片不直接写数据；选择模板后预填现有创建弹窗，确认后才添加草稿。

### 使用方式
模板名称、说明、步数和步骤标签均从 workflowTemplates 的同一份定义派生；不在 UI 复制模板数据。桌面双列、窄屏单列，内容靠上、限宽、左对齐。复用 VButton，现成模板可编辑，空白流程不预置业务字段。

## FlowEditor

### 功能
按顺序展示节点、负责人、执行要求和状态，选择节点后直接编辑或查看运行详情。

### 适用范围
当前顺序流程；不提供分支或循环的假象。普通 Agent、人工确认、输入和交付采用图标及文本，状态不能只靠颜色。

### 使用方式
使用 ol/li 和 VNativeButton 绘制单列节点，顺序号与连接线保持阅读方向。中央内容滚动，节点卡片最大宽度受限，长名称/说明截断但保留可访问名称与配置全文。颜色与字号沿用 VUI 语义 token，支持浅色和深色；顶部保存为桌面主要保存入口，窄屏检查栏保留保存入口。

## 验证边界

验证空白、加载、失败、模板创建、节点编辑、保存反馈、运行停止状态及桌面/窄屏布局；真实模型执行与发布属于另外的验收面。
