# Launcher notifications

## LauncherNotificationTopbar

### 功能

Launcher 主窗口右侧顶栏统一承接助理页面的读取异常，恢复后自动移除。它只提供界面投影，不持有 Session、Turn、transcript 或任务的第二份状态。普通聊天与虚拟人会话核心不受影响。

### 适用范围

仅 Launcher 主窗口的助理页面级读取异常；发送、审批和任务执行仍由原有操作 owner 负责。

### 使用方式

`LauncherShell` 在壳内挂载 `LauncherNotificationProvider`，`LauncherTitlebar` 组合 `LauncherNotificationTopbar`；来源通过 `usePublishLauncherNotices` 发布当前读取状态，卸载或恢复时撤回。没有宿主的独立助理浮窗保留原有原地恢复路径。重试始终调用来源最近一次渲染的现有读取回调，避免身份切换后调用旧会话。相同来源的轮询不重复积累通知。

顶栏保留紧凑入口，不显示重复数量。点击既有 `VPopover` 打开右对齐提醒：每条默认仅显示通俗问题、展开箭头和恢复按钮，不另加标题、长说明或底部提示。读取异常以 `features` 标记聊天、待确认操作、任务进度和助理信息，在同一条提醒中合并展示受影响功能；合并只服务界面，不认定共同根因。聊天与任务同时未刷新时显示“聊天和任务进度没刷新”，只剩任务时显示“暂时查不到任务进度”。提醒数量仅用于无障碍标签，并按展示分组统计。外观等其他提醒仍独立显示。

标题通过 `VButton` 展开受影响功能；诊断再用 `VErrorSummary` 单独折叠为“错误详情”。读取超时以时钟而非断网图标表达，诊断提取已知错误标识并保持有界。读取恢复按钮统一为“再试一次”，进行中显示“正在刷新…”与“请稍等”。它调用当前各来源已有的读取回调，等所有读取结束后再解除重复触发锁；一个来源失败不能提前解锁其他读取。成功来源按原有逻辑撤回，只保留尚未恢复的功能，不显示伪造的成功时间或任务完成结果。此处不重发消息、审批决定或管理写入。

首次加载失败保留对话区域的短占位，详细错误和恢复动作在顶栏；发送结果未确认、审批决定失败、真正的待授权和待回答事项仍在对应操作附近直接呈现。全局主题动作的结果未确认也保留原操作恢复路径。顶栏无错误时只表达“暂无异常”，不把没有错误误报为已确认连接成功。

### 视觉与交互

沿用 Launcher 的 VUI/shadcn、字重、语义色和密度，不建立新的 VUI primitive、通知服务或操作系统通知。保留原生窗口按钮的右侧空间和拖动边界，通知入口为 no-drag。窄于 520px 时隐藏可见短标签与品牌字样，入口的完整无障碍标签保留；浮层受视口宽高约束，内容可滚动。Escape、外部点击和关闭按钮复用 Radix 的焦点恢复与关闭行为。网页面板复用既有遮挡保护：VUI popover 打开期间撤下原生网页 bounds，关闭后恢复，避免原生网页盖住通知。

恢复事件在对话历史中仍保留真实事件、次数和时间。`conversationSpecialRows` 将 `session_recovery_resumed` 渲染成无背景、无边框的紧凑记录行，不改 Journal、事件顺序或次数，也不影响 CLI 生命周期卡片。

### 验证

任务侧栏仅保留分类数量、任务条目和刷新操作。团队状态读取失败、部分状态未核验等警告进入顶栏，成功刷新后撤回；历史范围有限、旧关联无法恢复不再作为常驻段落显示。

原生团队页的 `state=partial` 同时表达历史覆盖缺口和当前读取不完整。只有 `legacyUnrecoverable>0`、`invalidRecords=0` 且本页所有现有任务均为 `readState=ready`（含零任务）时，该页不发布“任务进度读不到”的提醒；原始 `state`、`coverage` 与历史记录仍保留，不将缺失历史改写成已修复。当前存在 unknown 任务、同页或跨页的冲突观测、无明确历史原因的 partial、坏记录或读取异常时，提醒继续保留。传输失败沿用现有有限探测与手动重试，不借本次修复增加无限轮询、不自动重发失败任务。

覆盖跨来源读取失败的紧凑合并、部分恢复、诊断按需展开、外观降级、来源恢复和卸载、身份切换后重试回调、全部读取结算前的重试锁、真实浮层关闭/焦点、中英文与桌面/窄屏布局。普通会话恢复记录保留原事实，并验证不再使用大卡片背景。

页面任务读取缓存按助理与聊天身份隔离，保持窗口打开时切换身份也重新读取；旧身份的错误不投影到新身份。任务侧栏的有限错误探测预算随身份切换重置，当前身份仍保留既有次数上限。历史附件切换聊天后自动调度可见附件，旧聊天的延迟结果不得写入新聊天缓存；读取恢复后清除对应提醒，未恢复的真实错误继续显示。
