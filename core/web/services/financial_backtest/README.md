# Historical AI backtests

`financial_backtest_service.py` is the public facade; the router only parses typed requests and maps domain errors. The existing MA endpoint remains compatible.

The Agent-owned private artifact store is the authority for previews, immutable inputs, accepted decisions and simulation results. It is separate from native Session transcripts and the paper account. Runs never submit broker or paper-account orders and never update Agent memory. Preview reads public historical data without invoking a model. Starting a UUID-idempotent run explicitly authorizes its frozen decision and token limits.

`data.py` fetches bounded yearly Tencent raw and qfq windows with warm-up. It validates OHLC, volume, dates, ordering, duplicate observations, requested endpoints and in-range dates against the same provider's Shanghai index calendar. Missing sessions are blocked because a source gap cannot be distinguished reliably from a halt. The index is not an official exchange audit source. Raw/qfq quantization intervals detect material changes in the adjustment transform; detected corporate actions block the run. The provider supplies no authoritative corporate-action ledger, so tiny or complex actions may still escape detection. Data hashes retain reproducibility; a passed factor check must never be described as proof of no corporate action.

`engine.py` owns deterministic long-only, cash-account simulation: 100-share lots, T+1 sellability, completed-close decisions, next-open fills, bounded OHLC slippage, commission with minimum fee and historical date/side-specific stamp duty. Zero-volume and locked/one-price bars are conservatively rejected. Order records explain no-action and rejection outcomes. Queue priority, exact historical ST/listing regimes, partial fills, transfer/regulatory fees and corporate-action cash/share changes are not modeled. The engine is a research simulation and cannot establish real execution availability.

Strategy and buy-and-hold use the same cost/execution rules, daily close marks and initial cash. Terminal positions remain marked to close rather than assuming a sale. Risk/return, fees, trade counts and realized-position win rates come from deterministic ledger calculations. An unclosed position has no realized win rate. Sparse or degenerate series must produce unavailable statistics rather than fabricated Sharpe values.

`decision.py` invokes the existing configured model through the unified stateless LLM adapter, with no tools, current Agent memory, persona or conversation transcript. Each input consists of a bounded price prefix ending on the decision date, the simulated portfolio at that date, frozen strategy/parameters and the exact output contract. Public `targetWeight` is a percentage from 0 to `maxPositionPct`; the engine receives a ratio after explicit conversion. Invalid JSON, wrong dates, missing reasons, nonfinite numbers and excessive positions stop that step, never silently becoming hold signals. Model training hindsight cannot be eliminated, so results are not prospective accuracy measurements.

The dedicated inference profile caps output at 512 tokens and disables automatic transport retries. Qwen thinking is explicitly disabled without mutating the operator configuration. Other configurations with explicitly enabled reasoning are rejected during preview; intrinsic model reasoning can still consume the cap, and truncated or malformed output requires explicit recovery. Preview, execution and drift checks share the same effective profile. The exported model configuration hash contains no credentials. A separate portfolio margin keeps preview reservations valid as account values change.

`service.py`, `store.py` and `runtime.py` own atomic persistence, cross-process coordination, managed background work, stop/resume, budgets, idempotency and export. An invocation is persisted before calling the provider. A crash or unknown result cannot be automatically resent: the public `paused_unknown` state requires confirmation for the exact decision date and possible duplicate charge. Successful decisions are retained during recovery. The configured model and frozen input hashes remain bound to the run; provider/configuration drift must fail closed. JSON retains provenance and audit records. CSV escapes formula-like text cells.

Lifecycle logs record only stable Agent/run/date identifiers, state, reason codes and counts; model prompts, responses, keys and portfolio contents are not logged. Tests cover accounting, no-future input, malformed decisions, persistent recovery, duplicate starts, scoped reads, HTTP serialization and desktop controls. Runtime and browser acceptance are distinct from unit tests.
