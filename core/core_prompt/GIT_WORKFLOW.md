# Git Workflow

## 提交模板

- `fix: ...` 修复可观察错误或 CI 失败。
- `feat: ...` 添加用户可见能力。
- `test: ...` 增加或校正测试保护。
- `docs: ...` 更新说明、计划或项目记忆。

## 拆提交规则

- 每个提交只覆盖一个明确目标。
- 只暂存本轮相关文件，避免 `git add .`。
- 提交前查看 `git status --short --branch` 和 staged diff。
- 不混入未验证的本地实验、运行产物或无关清理。

## 高风险改动

- 共享热点文件只做最小改动。
- 推送前跑与改动范围匹配的测试或检查。
- 不回滚用户已有改动，除非用户明确要求。
- 发现新失败时先记录具体测试、日志或 CI run 证据。

## 反模式

- 把 unrelated cleanup 塞进功能提交。
- 为了通过 CI 随手降低测试断言。
- 在脏工作区里无法说明每个 staged 文件来源。
- 提交 secrets、本地配置、缓存、日志或临时文件。
